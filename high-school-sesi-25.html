def tambah_transaksi(tanggal, keterangan, nominal, tipe):
    tanda = "+" if tipe == "masuk" else "-"
    baris_data = f"{tanggal} | {keterangan} | {tanda}Rp{nominal:,}\n"

Masalah: Data Bisa Hilang

Bayangkan kamu membuat pencatat uang saku. Setiap pembelian masuk ke List bernama riwayat. Saat kamu memilih menu “Lihat Riwayat”, isi List ditampilkan dengan benar. Namun, List tersebut berada di memori program, bukan otomatis disimpan ke file.

Jika runtime dimulai ulang, variabel yang dibuat sebelumnya harus didefinisikan lagi; data yang hanya ada di List tidak otomatis kembali. Inilah keterbatasan state management yang sebelumnya kamu pelajari.

Dengan File Handling, kita mencatat transaksi dalam berkas terpisah. Tujuannya bukan mengganti seluruh List/Dictionary, melainkan menyediakan tempat penyimpanan yang dapat dibaca kembali oleh program.

RAM vs File

RAM adalah memori kerja komputer. Python menggunakan RAM untuk menyimpan List, Dictionary, variabel, dan objek yang sedang diproses. RAM membantu program berjalan cepat, tetapi data di sana bersifat sementara.

File seperti .txt tersimpan di sistem berkas. Ketika Python membuka file itu lagi, isi file dapat dibaca tanpa harus mengandalkan List lama. Pada komputer pribadi dengan penyimpanan tetap, file dapat bertahan setelah program ditutup.

Khusus Google Colab: file yang ada di panel Files biasanya berada pada penyimpanan runtime yang sifatnya sementara. Restart kernel pada runtime yang sama berbeda dengan mendapatkan runtime baru. Karena itu, simpan notebook dan unduh/backup file penting sesuai arahan guru.

File I/O: Tiga Langkah

Setiap operasi file dapat dipahami sebagai tiga langkah. Open: Python membuka hubungan dengan file dan memeriksa mode yang digunakan. Process: program membaca atau menulis isi file. Close: hubungan dengan file ditutup supaya sumber daya sistem dilepaskan.

Kita tidak perlu memanggil close() secara manual jika memakai with open(...). Python akan mengurus penutupannya saat blok with selesai, termasuk ketika ada exception.

Kebiasaan ini penting untuk program pencatatan transaksi: kode harus jelas menentukan file mana yang dikelola, apa operasinya, dan kapan operasi selesai.

Mengenal with open()

Perhatikan bentuk with open(nama_file, mode, encoding=...) as f:. Hanya baris yang berada di dalam blok berindentasi yang memakai file terbuka tersebut. Setelah keluar dari blok, file ditutup secara otomatis.

Pada contoh ini, mode a dipilih agar transaksi baru ditambahkan ke bagian akhir file. f.write(...) menuliskan string sesuai isi yang kita berikan. \n berarti pindah baris; tanpa itu, transaksi berikutnya berisiko menempel pada baris yang sama.

encoding="utf-8" membantu menangani teks lintas sistem. Walau begitu, jangan menganggap parameter ini sebagai enkripsi atau perlindungan file.

Mode w, a, dan r

w berarti write. Jika file belum ada, Python membuatnya. Jika file sudah ada, isinya dikosongkan sebelum penulisan baru. Karena itu, w tidak aman untuk mencatat transaksi baru ke riwayat lama.

a berarti append. Mode ini menambahkan teks di bagian akhir file, sehingga cocok untuk riwayat transaksi. Namun, jika kamu menjalankan cell tambah transaksi berulang-ulang, baris yang sama dapat tertulis lebih dari sekali.

r berarti read. Mode ini membaca isi file tanpa membuka izin untuk menulis. Jika filenya tidak ditemukan, program dapat menghasilkan FileNotFoundError.

Mini Check: Pilih Mode

Pilihan yang tepat adalah a. Konsepnya sederhana: transaksi harian adalah riwayat. Menambah informasi baru tidak seharusnya menghilangkan informasi sebelumnya.

Untuk membaca, gunakan r. Memakai w hanya untuk melihat isi file adalah kesalahan besar karena mode tersebut dapat mengosongkan berkas sebelum kamu membaca apa pun.

Pada project nanti, kita memisahkan operasi ini dalam function yang berbeda agar risiko salah mode lebih kecil: inisialisasi_file(), tambah_transaksi(), dan baca_semua_transaksi().

Apa yang Terjadi dengan w?

Kedua blok kode di slide menggunakan mode w pada nama file yang sama. Saat blok kedua dijalankan, isi file sebelumnya tidak digabung. File dibuka untuk penulisan baru, sehingga hanya Saldo: 500 yang tertinggal.

Kesalahan ini sering muncul ketika fungsi “Tambah Transaksi” tanpa sengaja memakai mode w. Program mungkin tetap mencetak pesan “berhasil”, tetapi transaksi lama sebenarnya sudah hilang.

Di Teacher Project, fungsi inisialisasi menggunakan w hanya jika file belum ada. Dengan pengaman tersebut, header tidak ditulis ulang setiap kali notebook dijalankan.

Interaktif: Uji Perilaku Mode File

Gunakan tombol a beberapa kali untuk melihat cara baris baru bertambah tanpa menghapus baris sebelumnya. Perhatikan juga bahwa menekan tombol yang sama berkali-kali akan menghasilkan baris duplikat. Python tidak otomatis mengetahui bahwa kamu sedang menguji, bukan mencatat transaksi baru.

Sekarang klik w. Isi awal diganti dengan teks baru. Perilaku ini menjelaskan mengapa mode w tidak dipakai dalam fungsi append. Klik r untuk membaca isi file saat ini tanpa mengubahnya.

Dalam praktik, jangan gunakan file transaksi penting untuk menguji mode yang berisiko. Pakailah file uji terpisah, misalnya uji.txt.

Membaca File dengan r

Saat sebuah file dibuka dengan mode r, kamu dapat memanggil f.read() untuk mengambil seluruh isinya. Nilai kembalian berupa satu string yang juga memuat karakter perpindahan baris.

Setelah isi file ditampung ke variabel isi_file, print(isi_file) menampilkannya di terminal. Jika file memuat header dan tiga transaksi, semua bagian itu akan terlihat.

Namun, mode r mengharapkan file sudah tersedia. Jika belum ada, Python tidak otomatis membuatnya. Karena itu, function pembaca kita akan memeriksa keberadaan berkas terlebih dahulu.

Periksa File dengan os.path.exists()

Modul os menyediakan beberapa fungsi untuk bekerja dengan sistem operasi. Salah satunya os.path.exists(path), yang mengembalikan True jika path tersebut tersedia dan False jika tidak.

Kita memakai pengecekan ini untuk dua hal. Pertama, saat inisialisasi: if not os.path.exists(FILE_TRANSAKSI) berarti buat file baru hanya ketika file belum ada. Kedua, saat membaca: tampilkan riwayat jika file ada; jika tidak, berikan pesan yang mudah dimengerti.

Pengecekan path membuat alur program lebih jelas, tetapi tidak menggantikan seluruh error handling. Pada aplikasi yang lebih besar, operasi I/O juga perlu mempertimbangkan izin akses, disk penuh, dan perubahan file di luar program.

Kenapa Perlu UTF-8 dan Baris Baru?

Encoding mengatur bagaimana karakter teks diterjemahkan menjadi byte. Menggunakan utf-8 secara eksplisit membantu mengurangi masalah perbedaan encoding antara lingkungan komputer. Untuk membaca file yang sama, pakailah encoding yang cocok dengan encoding saat file ditulis.

Karakter \n adalah newline: penanda agar tulisan berikutnya dimulai pada baris yang berbeda. Tanpa karakter ini, file dapat terlihat seperti “Uang SakuBeli BukuMakan Siang” dalam satu baris panjang.

Pada Lesson 26, kamu juga akan bertemu parameter newline="" saat membuat CSV. Walaupun namanya mirip, itu adalah pengaturan pembukaan file untuk modul CSV, bukan teks akhir baris yang kita tambahkan pada setiap transaksi TXT.

Project Step 2: Tambah Transaksi

Function tambah_transaksi() pada Teacher Project menggunakan empat parameter: tanggal, keterangan, nominal, dan tipe. Keempatnya dipakai untuk menyusun satu baris catatan.

Baris tanda = "+" if tipe == "masuk" else "-" memberi awalan plus untuk pemasukan dan minus untuk pengeluaran. Perhatikan: ini hanya mengatur tampilan teks, bukan menghitung saldo otomatis. Nominal dalam fungsi tetap nilai yang diberikan.

Bagian terpenting adalah open(...,"a",...). Function ini harus menambahkan data ke akhir file. Jangan menggantinya menjadi w. Pada data nyata, validasi tipe juga diperlukan; di latihan ini gunakan nilai dummy "masuk" atau "keluar" sesuai contoh.

Membaca f-string Transaksi

Format yang dipakai Teacher Project adalah Tanggal | Keterangan | ±Nominal. Tanggal dan keterangan menjelaskan transaksi; tanda + atau - menunjukkan jenisnya.

Dalam f-string, ekspresi {nominal:,} mengubah tampilan angka menjadi bentuk dengan pemisah ribuan. Ini mempermudah pembacaan nominal di terminal. Perhatikan bahwa pemisah ribuan yang muncul pada contoh Python adalah koma, bukan titik seperti kebiasaan penulisan Rupiah di Indonesia.

Setelah pemanggilan fungsi selesai, satu baris teks disimpan dalam buku_kas.txt. File TXT ini masih berupa catatan berformat manusia, belum menjadi tabel dengan kolom yang diatur secara eksplisit.

Project Step 3: Baca Riwayat

Setelah mampu menyimpan data, program juga harus bisa membacanya. Itulah tugas function baca_semua_transaksi(). Kode di slide menunjukkan inti fungsi yang sama dengan Teacher Project.

Pertama, pengecekan os.path.exists() memastikan file sudah tersedia. Kedua, mode r digunakan untuk membaca, bukan menulis. Ketiga, f.read() mengambil seluruh isi file dan print() menampilkannya.

Jika file tidak ditemukan, program memberi pesan peringatan alih-alih langsung mencoba membuka file yang tidak ada. Saat praktik, coba panggil function ini setelah mencatat dua atau tiga transaksi; pastikan transaksi awal tetap tercantum.

Pengujian perlu dilakukan berurutan. Mulai dari kondisi file belum tersedia, jalankan inisialisasi, tambahkan data, lalu baca kembali. Selanjutnya tambahkan satu transaksi lagi dan pastikan transaksi sebelumnya tidak berubah.

Uji pembacaan tanpa menjalankan ulang cell penambahan. Hasilnya harus sama dengan isi sebelumnya. Ini membuktikan bahwa operasi baca tidak merusak file.

Jika ingin menguji dari kondisi benar-benar bersih, buat file uji baru atau reset data simulasi secara sadar. Jangan menghapus atau menimpa bukti kerja yang sudah selesai.

Detektif Bug: Riwayat Mendadak Hilang

Bug ini berbahaya karena tidak selalu membuat program crash. File masih berhasil dibuka dan baris baru masih tertulis. Namun, setiap transaksi sebelumnya telah terhapus.

Perbaikan paling langsung adalah menggunakan mode a untuk operasi penambahan. Setelah memperbaiki kode, uji dua transaksi berurutan dan pastikan keduanya masih ada.

Jika data sudah tertimpa, mengganti mode menjadi a tidak otomatis mengembalikan riwayat yang hilang. Karena itu, debugging perlu disertai kebiasaan membuat cadangan serta menguji mode berisiko pada file contoh.

Detektif Bug: File Tidak Bisa Ditulis

File dibuka dengan mode r, yang hanya memberi akses baca. Karena itu, pemanggilan f.write() tidak sesuai dengan kemampuan objek file yang sedang dibuka.

Jika tujuannya menambah catatan, ubah mode menjadi a. Jika tujuannya membaca, pertahankan r tetapi ganti operasinya menjadi f.read().

Saat membaca error Python, cari pasangan penyebab dan tindakan: fungsi apa yang dipakai, mode akses apa yang aktif, dan operasi apa yang sebenarnya kamu inginkan. Mengganti seluruh kode tanpa memahami penyebab biasanya tidak diperlukan.

Detektif Bug: File Hilang / Baris Menempel

Jika Python menampilkan FileNotFoundError, jangan langsung menyalahkan fungsi read(). Pastikan file memang tersedia di direktori yang dipakai, fungsi inisialisasi pernah dijalankan, dan ejaan nama file tidak berbeda.

Masalah lain tidak selalu menimbulkan exception. Misalnya, semua transaksi tersimpan, tetapi satu baris menempel pada baris berikutnya. Penyebab umumnya adalah string yang ditulis tidak memiliki \n di bagian akhir.

Bedakan bug yang menghentikan program dengan bug yang membuat hasil kurang tepat. Keduanya perlu diuji, tetapi pendekatan penanganannya bisa berbeda.

Penyimpanan di Google Colab

Google Colab menjalankan kode pada komputer virtual. File yang dibuat dengan nama relatif seperti buku_kas.txt biasanya berada di direktori kerja runtime tersebut. Kamu dapat membuka dan mengunduhnya dari panel Files.

Jangan menyamakan “saya sudah menyimpan notebook” dengan “file TXT hasil program sudah aman tersimpan”. Menyimpan notebook tidak otomatis menjadikan semua file runtime sebagai arsip permanen. Ikuti instruksi guru untuk menyimpan atau mengunduh output yang diminta.

Jika ingin membuktikan persistensi dalam runtime yang sama, jalankan ulang pembacaan setelah me-reset variabel. Tetapi jangan membuat klaim bahwa file pasti tetap ada setelah runtime Colab diganti.

Integritas Data dan Privasi

Dalam pencatatan keuangan, riwayat transaksi sering dipakai untuk memeriksa asal sebuah perubahan saldo. Catatan semacam ini disebut audit trail. Di latihan kita, menggunakan mode append adalah cara sederhana untuk memperkenalkan kebiasaan mencatat peristiwa secara berurutan.

Perlu diketahui, a pada file TXT bukan pengamanan audit log yang tidak dapat dimanipulasi. File teks masih dapat diubah atau dihapus oleh pengguna yang punya izin. Sistem profesional memerlukan pengaturan akses, validasi, cadangan, serta kontrol tambahan.

File TXT juga tidak terenkripsi secara otomatis. Hindari memasukkan nomor rekening asli, password, identitas pribadi, dan catatan transaksi sensitif.

Extension Challenge: Menu Transaksi

Tantangan dalam Teacher Project adalah membuat interaksi berbasis while True. Dengan begitu, siswa tidak perlu mengubah kode setiap kali ingin menambahkan transaksi.

Gunakan input() untuk meminta informasi, lalu panggil function yang sudah ada. Kamu dapat menggunakan kembali keterampilan try-except ValueError dari Semester 1 agar nominal yang bukan angka tidak langsung menyebabkan program berhenti.

Tetap periksa fungsi utama sebelum menambah fitur. Tantangan ini adalah pengayaan; target minimum Lesson 25 adalah file tercipta, transaksi dapat di-append, dan riwayat bisa dibaca ulang.
