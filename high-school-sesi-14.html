Kenapa Kode Berulang Perlu Dirapikan?

Kode berulang memang bisa berjalan, tapi kurang nyaman dipelihara. Kalau nanti rumus berubah, kamu harus mencari semua tempat yang memakai rumus itu.

Di project kecil, ini mungkin belum terasa. Namun saat aplikasi CLI punya banyak fitur, copy-paste rumus bisa membuat bug muncul di banyak tempat. Function membantu membuat satu pusat logika yang jelas.

Prinsip sederhana

Kalau ada pola kode yang dipakai berkali-kali, pertimbangkan untuk menjadikannya function.

Analogi Mesin Input-Process-Output

Function bisa dibayangkan seperti mesin kecil. Kamu memasukkan bahan, mesin memprosesnya, lalu mesin mengeluarkan hasil. Dalam konverter kurs, bahan masuknya adalah nominal dan kurs.

Mesinnya tidak perlu tahu nama user atau cerita aplikasi. Tugasnya hanya satu: mengalikan nominal dengan kurs. Semakin jelas tugas function, semakin mudah function itu dites dan dipakai ulang.

Pola yang akan dipakai

hasil = nominal * kurs

Membaca Struktur Function

Baris pertama function disebut header. Header dimulai dengan def, lalu nama function, tanda kurung untuk parameter, dan titik dua.

Baris di bawahnya harus menjorok ke dalam. Itulah body function. Body berisi pekerjaan yang dilakukan function. Pada contoh ini, function menghitung hasil konversi lalu mengembalikannya.

Bug umum

Lupa titik dua setelah header function atau lupa indentasi bisa membuat SyntaxError atau IndentationError.

Parameter vs Argument

Parameter adalah nama yang ditulis saat membuat function. Contohnya nominal dan kurs.

Argument adalah nilai nyata yang diberikan saat function dipanggil. Pada hitung_kurs(10, 15500), angka 10 masuk ke parameter nominal, dan 15500 masuk ke parameter kurs.

Analogi

Parameter seperti label kotak. Argument adalah benda yang kamu masukkan ke kotak itu.

Kenapa Return Penting?

Function yang memakai return bisa mengirim hasil agar dipakai lagi oleh kode lain. Misalnya hasil konversi bisa disimpan ke variabel, diformat, dibandingkan, atau ditampilkan.

Berbeda dengan print(), return tidak otomatis menampilkan teks ke layar. Return hanya mengembalikan nilai. Karena itu, setelah nilai dikembalikan, kita bisa memutuskan mau diapakan.

Pola penting

hasil_rupiah = hitung_kurs(10, 15500) berarti hasil return disimpan di variabel hasil_rupiah.

Membuat Function Tidak Sama dengan Menjalankannya

Saat Python membaca def hitung_kurs(...), Python menyimpan resepnya. Namun resep itu belum dijalankan.

Function baru bekerja ketika dipanggil, misalnya hitung_kurs(2, 15000). Saat dipanggil, Python memasukkan argument ke parameter, menjalankan isi function, lalu mengembalikan hasil.

Bug umum

Siswa sering menulis function dengan benar, tetapi lupa memanggilnya. Akibatnya output tidak muncul.

Menghubungkan Input dengan Function

Program CLI biasanya menerima input dari user. Karena hasil input() adalah string, data nominal perlu diubah menjadi angka sebelum masuk ke rumus.

Di contoh ini, float() dipakai agar user bisa memasukkan angka desimal seperti 10.5. Setelah itu, nilai tersebut masuk ke function hitung_kurs().

Alur yang terjadi

User mengetik nominal → Python mengubah ke float → function menghitung → hasil dicetak dengan f-string.

Reusability

Reusable berarti bisa dipakai ulang. Function yang baik bisa dipanggil berkali-kali dengan data yang berbeda.

Untuk konverter kurs, rumus dasarnya sama untuk banyak mata uang: nominal dikali kurs. Karena itu, function membuat program lebih bersih. Kamu cukup mengganti argument, bukan menulis ulang rumus.

Contoh

hitung_kurs(10, 15500), hitung_kurs(20, 11500), dan hitung_kurs(5, 17000) memakai function yang sama.

Latihan Membaca Kode

Function menerima nominal = 5 dan kurs = 15000. Baris return menghitung 5 * 15000.

Hasilnya adalah 75000. Karena hasil return disimpan ke variabel hasil, maka print(hasil) menampilkan angka tersebut.

Cara membaca cepat

Masukkan argument ke parameter, jalankan rumus di return, lalu lihat nilai yang disimpan.

Berpikir Modular

Berpikir modular berarti memecah program menjadi bagian kecil yang punya tugas jelas. Sebelum menulis function, tanyakan: function ini bertugas melakukan apa?

Untuk hitung_kurs(), tugasnya menghitung nilai Rupiah. Karena tugas itu membutuhkan nominal dan kurs, maka dua data tersebut menjadi parameter.

Jangan terlalu banyak tugas

Function yang terlalu banyak tugas jadi sulit dibaca. Untuk awal, satu function sebaiknya fokus pada satu pekerjaan.

Dengan kurs tetap, kamu bisa menghitung manual lalu membandingkan dengan output program. Ini penting untuk memastikan function bekerja benar.

Mengecek Output

Output yang baik membantu user memahami hasil tanpa melihat kode. Header menunjukkan nama program. Daftar kurs memberi petunjuk pilihan. Bagian hasil menampilkan nominal, kurs, dan hasil akhir.

Saat mengecek program, jangan hanya melihat apakah ada output. Pastikan hitungannya benar. Untuk case 100 USD, hasil manualnya adalah 1.550.000 Rupiah.

Kebiasaan testing

Selalu bandingkan minimal satu output program dengan hitungan manual.

Testing dengan Case Berbeda

Testing bukan hanya menjalankan program satu kali. Kamu perlu mencoba beberapa mata uang untuk memastikan function dan dictionary bekerja bersama.

Case valid memastikan rumus berjalan. Edge case membantu melihat batas program. Misalnya, input usd dengan huruf kecil bisa gagal karena dictionary menyimpan key USD.

Target testing

Minimal coba satu case USD, satu case mata uang lain, dan satu case salah input.

Trace Table

Trace table membantu kamu melacak nilai dari awal sampai akhir. Ini sangat berguna saat program sudah memakai function, dictionary, dan input sekaligus.

Untuk 50 SGD, program mengambil kurs 11.500 dari dictionary. Function menghitung 50 × 11.500, lalu mengembalikan 575.000.

Gunakan saat debug

Kalau hasil output salah, buat trace table kecil di catatanmu untuk melihat nilai mana yang mulai melenceng.

Membedakan Return dan Print

Ini salah satu bagian yang sering membingungkan. print() hanya menampilkan sesuatu ke layar. Setelah ditampilkan, nilainya tidak otomatis bisa dipakai untuk perhitungan lain.

return mengirim nilai keluar dari function. Nilai itu bisa disimpan ke variabel, lalu dipakai lagi. Karena project ini membutuhkan hasil konversi untuk diformat, return lebih tepat untuk function hitung.

Aturan sederhana

Kalau hasilnya perlu dipakai lagi, gunakan return.

Debugging: Tidak Ada Output

Kalau function sudah dibuat tetapi tidak ada output, cek apakah function sudah dipanggil. Membuat function hanya menyimpan resepnya.

Tambahkan pemanggilan seperti print(hitung_kurs(10, 15500)) atau simpan hasilnya ke variabel terlebih dahulu.

Checklist

  • Apakah function punya nama?
  • Apakah body function sudah benar?
  • Apakah function sudah dipanggil?

Debugging: Function Mengembalikan None

Jika function tidak memiliki return, Python akan mengembalikan None. Artinya, function selesai berjalan tetapi tidak mengirim nilai yang bisa dipakai.

Untuk memperbaikinya, tambahkan return hasil di akhir function. Pastikan baris return masih berada di dalam indentasi function.

Fix

return hasil memberi tahu Python nilai mana yang harus dikirim keluar dari function.

Debugging: Argument Kurang

Jumlah argument saat memanggil function harus sesuai dengan jumlah parameter yang dibutuhkan. Jika function punya dua parameter, panggil dengan dua argument.

Untuk hitung_kurs(nominal, kurs), panggilan yang benar misalnya hitung_kurs(10, 15500). Angka pertama masuk ke nominal, angka kedua masuk ke kurs.

Urutan juga penting

Jika argument tertukar, program mungkin tetap berjalan, tetapi hasilnya bisa tidak sesuai maksud.

Membaca ValueError

ValueError muncul ketika Python menerima nilai yang bentuknya tidak sesuai. Untuk float(), input seperti sepuluh tidak bisa ditebak menjadi angka.

Di sesi ini, cukup kenali penyebabnya. Kamu sudah pernah belajar try-except, jadi challenge lanjutan bisa menambahkan pengaman agar program tidak crash.

Input yang lebih aman

Gunakan angka seperti 10, 10.5, atau 1000. Untuk desimal, Python memakai titik, bukan koma.

Debugging: KeyError

Dictionary sangat literal. "USD" dan "usd" dianggap berbeda. Jika key tidak ada, Python memunculkan KeyError.

Solusi sederhana: tampilkan daftar pilihan yang jelas dan minta user mengetik sesuai pilihan. Solusi lanjutan: ubah input menjadi huruf besar dengan .upper() atau cek dulu apakah key ada.

Clean UX di CLI

Berikan pilihan input yang jelas: USD / SGD / EUR / JPY.

Challenge: Memperluas Data

Karena kurs disimpan di dictionary, menambah mata uang baru cukup dilakukan dengan menambah pasangan key-value baru.

Function hitung_kurs() tidak perlu diubah. Ini bukti bahwa function yang dibuat dengan parameter bisa dipakai untuk data baru selama bentuk datanya masih sesuai.

Yang perlu dijaga

Pastikan key konsisten dan kurs memakai angka. Jangan menaruh teks seperti "sepuluh ribu" untuk nilai kurs.

Reading Code Function Format

Function format_rupiah() menerima angka 250000, lalu mengembalikan string yang sudah diformat.

Karena ada print() di luar function, hasil return ditampilkan ke terminal. Outputnya adalah Rp250,000.

Kenapa koma?

Format Python :,.0f memakai koma sebagai pemisah ribuan. Untuk latihan, ini sudah cukup agar angka lebih mudah dibaca.

Menuju Program yang Lebih Aman

Program dasar akan error jika user mengetik kode mata uang yang tidak ada. Versi lebih aman mengecek dulu apakah key tersedia di dictionary.

Pola if mata_uang in kurs_simulasi membantu program memberi pesan ramah, bukan langsung berhenti karena KeyError. Ini gabungan dari materi dictionary, if, dan function.

Refactoring berikutnya

Di project yang lebih besar, pengecekan input juga bisa dibuat menjadi function sendiri.

Checklist Debugging Sesi 14

Bug function biasanya datang dari struktur. Cek header function, titik dua, indentasi, jumlah argument, dan return.

Bug konverter kurs juga bisa datang dari dictionary. Jika key mata uang tidak cocok, program bisa gagal saat mengambil kurs.

Urutan cek yang disarankan

  1. Cek pesan error dan nomor baris.
  2. Cek struktur def.
  3. Cek apakah function dipanggil.
  4. Cek nilai input dan key dictionary.

Checklist Kualitas Project

Gunakan checklist ini sebelum mengumpulkan project. Jangan hanya mengecek apakah program bisa jalan. Cek juga apakah function benar-benar modular.

Kalau semua rumus masih ditulis langsung di banyak tempat, berarti project belum sepenuhnya modular. Pindahkan rumus ke function agar lebih rapi.

Yang tidak boleh lupa

Angka kurs harus diberi label sebagai simulasi. Jangan menampilkan project seolah-olah mengambil kurs real-time.

Readable Function

Kode yang baik bukan hanya berjalan, tetapi juga mudah dipahami. Nama function sebaiknya menjelaskan tugasnya.

hitung_kurs() memberi petunjuk bahwa function menghitung kurs. format_rupiah() memberi petunjuk bahwa function merapikan tampilan Rupiah. Nama seperti ini membantu teman dan gurumu membaca kode lebih cepat.

Tips

Gunakan kata kerja untuk function: hitung, format, tampilkan, validasi.

Rangkuman Sesi 14

Function membantu program menjadi lebih rapi. Daripada menulis rumus konversi berkali-kali, kamu membuat satu function yang bisa dipanggil dengan data berbeda.

Konsep ini akan sering dipakai di sesi berikutnya dan di final project CLI. Saat aplikasi makin besar, function membuat fitur lebih mudah dibangun, dites, dan diperbaiki.
