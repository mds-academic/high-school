Hubungan Project dengan Aplikasi Nyata

Kwitansi digital adalah versi sederhana dari output yang sering dibuat oleh sistem kasir, toko online, atau aplikasi pembayaran. Ketika transaksi terjadi, aplikasi perlu menampilkan informasi yang mudah dibaca.

Di balik tampilan kwitansi, ada data yang disimpan dan disusun. Program tidak menulis ulang semua kalimat setiap kali barang berubah. Program cukup mengambil nilai dari variabel, lalu menampilkannya di tempat yang sesuai.

Pola yang dipakai

Input Data: nama toko, barang, harga.
Process: Python menyimpan data dan menyusun teks.
Output: kwitansi tampil di terminal.

Hal yang tidak boleh muncul di kwitansi adalah data sensitif seperti password. Ini sekaligus mengingatkan bahwa aplikasi harus memilih data yang aman untuk ditampilkan.

Mengenal Google Colab

Google Colab adalah cloud notebook. Artinya, kamu bisa menulis Python di browser, menjalankannya, dan menyimpan notebook secara online. Untuk sesi awal, kita hanya memakai bagian yang paling penting.

Bagian yang perlu dikenali

  • Nama notebook: nama file project.
  • Text Cell: area untuk judul, catatan, atau instruksi.
  • Tombol Run: tombol untuk menjalankan isi code cell.
  • Code Cell: area tempat menulis kode Python.
  • Output Area: tempat hasil program muncul setelah cell dijalankan.

Jangan mengetik kode di Output Area. Output Area hanya menampilkan hasil. Jika ingin mengubah program, ubah kode di Code Cell, lalu tekan Run kembali.

Di Colab, satu notebook bisa berisi banyak cell. Pada sesi ini, cukup fokus pada satu atau beberapa cell sederhana agar konsep dasarnya jelas.

Bagian Penting Google Colab

Colab punya banyak menu, tetapi untuk hari pertama kamu tidak perlu memakai semuanya. Fokus pada area yang langsung berhubungan dengan menjalankan Python.

Yang perlu kamu kuasai hari ini

  • Nama Notebook: ganti dari Untitled menjadi nama project.
  • Text Cell: tempat menulis catatan atau instruksi, bukan kode Python.
  • Tombol Run: jalankan kode di code cell aktif.
  • Code Cell: tempat mengetik kode Python.
  • Output Area: tempat hasil muncul setelah program dijalankan.

Jika kode sudah diubah tetapi output masih sama, kemungkinan cell belum dijalankan ulang. Biasakan menekan Run setelah mengubah kode.

Kesalahan umum

Mengubah teks di output tidak mengubah program. Output adalah hasil, bukan tempat menulis kode.

Membedakan Tempat Menulis dan Tempat Melihat Hasil

Di Colab, Code Cell dan Output Area sering terlihat berdekatan. Namun, fungsinya berbeda. Code Cell adalah tempat menulis perintah. Output Area adalah tempat hasilnya ditampilkan.

Misalnya kamu menulis print("Halo") di Code Cell, lalu menekan Run. Tulisan Halo akan muncul di Output Area. Jika ingin mengganti hasil menjadi Halo Python, kamu harus mengubah kodenya, bukan outputnya.

Aturan sederhana

Ubah program di Code Cell → Run → lihat hasil di Output Area.

Memahami perbedaan ini akan membantu saat debugging. Banyak error awal terjadi karena siswa mengira output bisa diedit seperti teks biasa.

Memakai print()

print() adalah salah satu perintah paling dasar di Python. Fungsinya untuk menampilkan sesuatu ke output. Pada project kwitansi, print() dipakai untuk menampilkan garis, nama toko, nama barang, total harga, dan pesan penutup.

Format dasar

print("teks yang ingin ditampilkan")

Perhatikan tanda kurung dan tanda kutip. Teks biasa perlu ditulis di dalam tanda kutip. Jika tanda kutip hilang atau salah pasangan, Python bisa menampilkan error.

Yang harus hati-hati

  • print ditulis huruf kecil.
  • Teks ditulis di antara tanda kutip.
  • Kurung buka dan kurung tutup harus lengkap.

Di slide ini, editor memakai simulasi sederhana agar kamu bisa melihat output langsung. Saat praktik utama, kamu akan menjalankannya di Google Colab.

Membaca Kesalahan Dasar

Python cukup teliti. Salah huruf besar, tanda kutip, atau tanda kurung bisa membuat program tidak berjalan. Ini bukan masalah besar, asalkan kamu tahu bagian mana yang perlu dicek.

Checklist saat print() error

  • Apakah print ditulis huruf kecil?
  • Apakah teks berada di dalam tanda kutip?
  • Apakah ada kurung buka dan kurung tutup?
  • Apakah tanda kutipnya berpasangan?

Debugging sebaiknya dilakukan dari hal kecil dulu. Jangan langsung menghapus semua kode. Cek baris yang error, lalu bandingkan dengan format dasar yang benar.

Mindset penting

Error adalah petunjuk. Error memberi tahu bagian mana yang perlu diperiksa, bukan berarti kamu gagal belajar coding.

Memahami Variabel

Variabel bisa dibayangkan seperti laci berlabel. Labelnya adalah nama variabel, isinya adalah data. Jika kamu menulis nama_barang = "Buku Catatan", Python menyimpan teks Buku Catatan di dalam variabel bernama nama_barang.

Variabel membantu program menjadi dinamis. Daripada menulis nama barang di banyak tempat, kamu cukup menyimpannya sekali, lalu memanggil variabel itu saat dibutuhkan.

Contoh variabel pada kwitansi

  • nama_toko menyimpan nama toko.
  • nama_barang menyimpan barang yang dibeli.
  • harga_total menyimpan total harga.

Jika isi variabel diganti, output yang memakai variabel itu juga ikut berubah setelah program dijalankan ulang.

Nama Variabel yang Rapi

Nama variabel memengaruhi keterbacaan program. Untuk pemula, aturan paling aman adalah memakai huruf kecil dan garis bawah. Pola ini disebut snake_case.

Aturan minimum

  • Tidak memakai spasi.
  • Tidak diawali angka.
  • Gunakan nama yang menjelaskan isi data.
  • Konsisten huruf kecil dan garis bawah.

Python membedakan huruf besar dan huruf kecil. nama_barang dan Nama_Barang dianggap dua variabel yang berbeda. Ini bisa menyebabkan NameError jika kamu memanggil nama yang tidak sama persis.

Dalam project kwitansi, gunakan nama yang langsung menjelaskan fungsinya, seperti nama_toko, nama_barang, dan harga_total.

Menggunakan f-string

f-string adalah cara praktis untuk menggabungkan teks dengan variabel. Formatnya memakai huruf f sebelum tanda kutip, lalu nama variabel ditulis di dalam kurung kurawal.

Format dasar

print(f"Barang: {nama_barang}")

Bagian teks biasa akan tampil apa adanya. Bagian {nama_barang} akan diganti dengan isi variabel nama_barang. Inilah yang membuat output kwitansi bisa berubah tanpa perlu menulis ulang semua kalimat.

Yang sering salah

  • Lupa menulis huruf f sebelum string.
  • Salah menulis nama variabel di dalam { }.
  • Kurung kurawal tidak lengkap.

Merancang Output Sebelum Coding

Kwitansi yang rapi tidak langsung muncul begitu saja. Sebelum menulis kode, kamu perlu membayangkan bentuk output yang diinginkan.

Di sesi ini, output kwitansi dibagi menjadi beberapa bagian: header, data transaksi, footer, dan garis dekorasi. Pembagian ini membantu kamu menulis kode secara bertahap.

Kenapa perlu dipecah?

  • Lebih mudah mengecek error.
  • Lebih mudah mengganti data transaksi.
  • Lebih mudah membuat tampilan output rapi.
  • Lebih mudah menambah fitur bonus nanti.

Jika kamu langsung menulis semua baris tanpa rencana, kamu akan lebih sulit menemukan bagian yang salah. Developer biasanya memecah masalah menjadi bagian kecil terlebih dahulu.

Langkah Pertama Project

Langkah pertama adalah membuat variabel untuk menyimpan data transaksi. Data ini menjadi sumber informasi untuk kwitansi.

Minimal variabel

  • nama_toko
  • nama_barang
  • harga_total

Untuk sesi ini, harga boleh ditulis sebagai teks seperti "Rp125.000". Kita belum masuk ke perhitungan total otomatis. Fokusnya adalah menyimpan data dan menampilkan data tersebut dengan rapi.

Setelah variabel dibuat, jalankan program. Jika nama toko, barang, dan harga tampil di output, berarti data sudah berhasil disimpan dan dipanggil.

Menyusun Header

Header adalah bagian atas kwitansi. Biasanya berisi nama toko atau judul transaksi. Di Python terminal, kita bisa membuat header sederhana memakai print() dan garis dekorasi.

Garis seperti ============================== bukan perintah khusus. Itu hanya teks yang dicetak agar output lebih rapi dan mudah dibaca.

Kenapa memakai f-string?

Dengan f-string, nama toko di header mengambil isi dari variabel nama_toko. Jadi jika nama toko berubah, header ikut berubah saat program dijalankan ulang.

Pada tahap ini, jangan terlalu fokus membuat posisi teks sempurna. Yang penting struktur header sudah terlihat dan bisa berubah dari variabel.

Menampilkan Data Transaksi

Isi transaksi adalah bagian yang menjawab pertanyaan pembaca: barang apa yang dibeli dan berapa total harganya.

Di sini kamu menggunakan f-string lagi. Teks Barang : dan Total : adalah label yang membantu pembaca memahami informasi. Nilai di sebelahnya diambil dari variabel.

Tips kerapian

  • Gunakan label yang singkat.
  • Jaga jarak dan tanda titik dua agar output mudah dibaca.
  • Jangan menampilkan data yang tidak perlu.

Jika output menampilkan nama variabel secara literal, misalnya {nama_barang}, cek apakah kamu sudah menulis huruf f sebelum string.

Program Utama Sesi 1

Sekarang semua bagian digabung menjadi satu program. Program ini sudah memenuhi target dasar: ada variabel, ada output yang rapi, dan ada f-string untuk memasukkan nilai variabel ke dalam teks.

Yang terjadi di program

  1. Python menyimpan data transaksi di variabel.
  2. Python mencetak header kwitansi.
  3. Python menampilkan barang dan total harga menggunakan f-string.
  4. Python mencetak footer sebagai penutup.

Jika ingin mengubah transaksi, kamu cukup mengubah bagian variabel di atas. Baris print di bawah tidak perlu diubah satu per satu.

Jangan lupa

Setelah mengubah variabel, tekan Run lagi. Output lama tidak akan berubah otomatis jika program belum dijalankan ulang.

Menguji Program dengan Data Baru

Testing adalah bagian penting dari coding. Program tidak cukup hanya berjalan dengan data pertama. Program harus tetap masuk akal saat nilai variabel diganti.

Pada testing case ini, kamu mengganti barang menjadi Headphone dan harga menjadi Rp350.000. Setelah Run, output harus menampilkan data baru itu.

Yang dicek

  • Nama barang berubah menjadi Headphone.
  • Total harga berubah menjadi Rp350.000.
  • Tidak ada error.
  • Format output tetap mudah dibaca.

Jika output masih menampilkan data lama, biasanya cell belum dijalankan ulang atau kamu mengubah bagian yang tidak dipakai oleh print.

Testing dengan Data Pilihan

Setelah program berhasil dengan data contoh, coba data pilihanmu sendiri. Ini melatih kamu untuk membedakan data yang berubah dan struktur program yang tetap.

Ide penting

Bagian variabel adalah bagian yang paling sering diubah. Bagian struktur kwitansi, seperti garis, label, dan footer, biasanya tetap.

Kalau output preview terlihat benar, coba terapkan data yang sama ke program di Google Colab. Jalankan ulang cell dan bandingkan hasilnya.

Testing seperti ini membantu memastikan bahwa program tidak hanya menampilkan contoh dari guru, tetapi bisa dipakai untuk data transaksi lain.

Menganalisis Kode Sebelum Menjalankan

Salah satu kemampuan penting dalam coding adalah membaca kode. Tidak semua pemahaman harus dimulai dari Run. Kamu bisa melihat struktur program dan menebak bagian mana yang menyimpan data, bagian mana yang menampilkan output.

Pada contoh ini, tiga baris pertama adalah assignment atau pemberian nilai ke variabel. Tiga baris berikutnya adalah perintah print yang menampilkan nilai tersebut.

Cara membaca cepat

  • Jika ada tanda =, biasanya program sedang menyimpan nilai ke variabel.
  • Jika ada print(), program sedang menampilkan sesuatu.
  • Jika ada {nama_variabel} di f-string, program sedang mengambil isi variabel.

Kemampuan membaca kode akan sangat membantu saat debugging, karena kamu bisa menebak sumber masalah sebelum mengubah program.

Debugging Dasar Python

Debugging adalah proses mencari penyebab program belum berjalan sesuai rencana. Pada sesi pertama, error yang paling sering muncul biasanya masih berkaitan dengan typo, tanda kutip, atau lupa menjalankan ulang cell.

Urutan cek yang disarankan

  1. Baca pesan error atau gejala output.
  2. Cek baris yang baru kamu ubah.
  3. Cek tanda kutip, kurung, dan nama variabel.
  4. Jalankan ulang cell setelah memperbaiki.

Jangan langsung menghapus semua kode. Jika kamu menghapus semua kode, kamu kehilangan petunjuk. Perbaiki bagian kecil terlebih dahulu.

Contoh sikap developer

“Program belum sesuai. Aku cek variabelnya dulu, lalu cek f-string, lalu Run lagi.”

Dokumentasi Kode Sederhana

Komentar ditulis dengan tanda #. Komentar tidak dijalankan oleh Python. Fungsinya untuk memberi catatan kepada pembaca kode, termasuk dirimu sendiri saat membuka project lagi nanti.

Kapan memakai komentar?

  • Menandai bagian data transaksi.
  • Menandai bagian output kwitansi.
  • Menjelaskan langkah yang mungkin sulit dibaca.
  • Mengingatkan bagian yang akan dikembangkan nanti.

Komentar sebaiknya singkat dan membantu. Jangan menulis komentar yang terlalu panjang untuk kode yang sudah jelas. Contoh yang baik: # Data transaksi sebelum kumpulan variabel.

Kriteria Berhasil

Output minimum adalah target wajib. Jika target ini sudah selesai, berarti kamu sudah berhasil memahami inti sesi: menampilkan output, memakai variabel, dan memasukkan variabel ke teks.

Yang harus terlihat

  • Kwitansi tampil di Output Area.
  • Nama toko, barang, dan harga berasal dari variabel.
  • Jika isi variabel diubah, output ikut berubah setelah Run.
  • Tidak ada error Python.

Setelah output minimum aman, baru lanjut ke challenge. Jangan menambah fitur sebelum program dasar berjalan, karena error akan lebih sulit dicari.

Pengembangan Setelah Target Dasar

Challenge tidak wajib diselesaikan semua. Pilih satu tantangan yang sesuai dengan waktumu. Tujuannya adalah memperluas program tanpa merusak fitur utama.

Contoh pengembangan

Tambahkan nama_kasir = "Rina", lalu tampilkan dengan print(f"Kasir : {nama_kasir}").

Kalau menambah variabel baru, ingat dua langkah: buat variabelnya, lalu tampilkan dengan print atau f-string. Jika hanya membuat variabel tetapi tidak memanggilnya, output tidak akan berubah.

Prioritas tetap

Challenge dilakukan setelah program utama berjalan tanpa error. Jangan mengorbankan output minimum demi fitur tambahan.

Refleksi Konsep

Refleksi membantu memastikan kamu memahami alasan di balik langkah-langkah yang dilakukan. Jika kamu hanya menyalin kode tanpa memahami, kamu akan kesulitan saat data berubah atau saat terjadi error.

Jika kamu bisa menjawab pertanyaan itu dengan kata-kata sendiri, berarti dasar sesi ini sudah mulai kuat. Di sesi berikutnya, dasar ini akan dipakai lagi saat program mulai menerima input dari pengguna.
