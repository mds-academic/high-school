Kenapa Sesi Ini Penting?

Di sesi 17, kamu sudah membuat main menu loop. Program bisa menampilkan menu, membaca pilihan user, menjalankan fitur, lalu kembali ke menu. Masalahnya, kalau semua kode fitur ditaruh langsung di dalam loop, program akan cepat panjang dan sulit dibaca.

Sesi 18 adalah waktu untuk merapikan struktur. Kita akan memindahkan tiap fitur ke dalam function. Dengan begitu, main menu tidak lagi penuh dengan detail perhitungan. Main menu cukup bertugas mengarahkan pilihan user ke function yang tepat.

Gambaran besarnya

Main menu menjadi seperti resepsionis. Function menjadi ruangan kerja. User pilih menu, lalu program masuk ke function yang sesuai.

Alur Sesi

Hari ini kamu tidak membuat project yang benar-benar baru dari nol. Kamu melanjutkan prototype dari sesi 16 dan 17, lalu merapikan strukturnya agar lebih mudah dikembangkan.

Skill utamanya adalah decomposition: memecah masalah besar menjadi bagian kecil. Dalam coding Python, salah satu cara paling umum untuk melakukan itu adalah membuat function.

Fokus belajar

Bukan mengejar kode yang paling pendek. Fokusnya adalah membuat kode yang mudah dibaca, mudah dites, dan mudah diperbaiki.

Persiapan Coding

Buka notebook Sesi 18 dan siapkan project dari sesi sebelumnya. Kamu akan melihat pola yang sama: aplikasi CLI berbasis teks, ada input dari user, ada proses hitung, dan ada output berupa saran atau ringkasan.

Karena project bertema finansial, gunakan data latihan atau data dummy. Jangan memakai data keuangan pribadi yang asli. Untuk latihan, angka seperti pemasukan 2500000 atau target tabungan 1200000 sudah cukup.

Checkpoint awal

Sebelum refactor, pastikan kamu bisa menjelaskan fitur utama project: cek budget, target tabungan, keputusan beli, ringkasan terakhir, dan keluar program.

Dari Menu ke Struktur yang Lebih Rapi

Main menu loop membuat aplikasi terasa lebih interaktif. User tidak perlu menjalankan ulang program setiap kali ingin mencoba fitur lain. Namun, loop yang berisi semua detail fitur akan cepat menjadi terlalu ramai.

Bayangkan satu while True berisi perhitungan budget, target tabungan, keputusan beli, ringkasan, validasi input, dan pesan error. Program masih bisa jalan, tetapi sulit dirawat.

Masalah yang ingin kita bereskan

Main menu sebaiknya mengatur alur, bukan menampung semua detail perhitungan.

Function Bukan Sekadar Hiasan

Function dipakai ketika ada bagian kode yang punya tugas jelas. Misalnya: menampilkan menu, menghitung sisa budget, menghitung target tabungan bulanan, atau membuat rekomendasi pembelian.

Dengan function, kamu bisa mengetes satu fitur tanpa harus membaca seluruh program. Kalau fitur cek budget bermasalah, kamu bisa fokus ke function cek_budget() dulu, bukan membongkar semua main menu.

Manfaat praktis

  • Kode lebih pendek di bagian main menu.
  • Nama function membantu pembaca memahami tujuan kode.
  • Bug lebih mudah dilacak karena fitur dipisah.
  • Fitur baru lebih mudah ditambahkan.

Cara Membayangkan Alurnya

Ketika user memilih menu 1, program tidak perlu menulis semua langkah cek budget langsung di dalam loop. Program cukup memanggil function cek_budget(). Setelah function selesai, alur kembali ke main menu.

Ini membuat program terasa lebih teratur. Kamu bisa menambahkan atau memperbaiki satu ruangan fitur tanpa membuat lobby menjadi berantakan.

Contoh sederhana

elif pilihan == "1": last_summary = cek_budget(). Baris ini memberi tahu bahwa pilihan 1 menjalankan function cek budget dan menyimpan ringkasan terakhir.

Bagian-Bagian Function

def memberi tahu Python bahwa kita sedang membuat function. Nama function sebaiknya memakai kata kerja atau frasa yang menjelaskan tugasnya, seperti tampilkan_menu atau hitung_target_tabungan.

Parameter adalah data masuk. Tidak semua function butuh parameter, terutama kalau datanya langsung diambil dari input(). return dipakai untuk mengirim hasil kembali ke pemanggil function.

Ingat indentasi

Isi function harus menjorok ke dalam. Kalau indentasi salah, Python bisa bingung bagian mana yang termasuk function.

Function Tanpa Return

tampilkan_menu() adalah contoh function yang tugasnya memberi tampilan ke user. Function seperti ini boleh tidak memakai return, karena hasil utamanya adalah teks yang muncul di terminal.

Di project CLI, function ini membantu main menu terlihat bersih. Daripada menulis lima baris print() berulang-ulang di dalam loop, kamu cukup memanggil tampilkan_menu().

Kapan function tidak perlu return?

Ketika tugasnya hanya menampilkan informasi, mencetak instruksi, atau menjalankan aksi yang tidak perlu mengirim nilai balik.

Refactor Tidak Mengubah Tujuan Program

Ketika refactor, output program seharusnya tetap sama atau semakin jelas. Yang berubah adalah susunan kodenya. Dari kode panjang di dalam if, kita pindahkan ke function dengan nama yang lebih mudah dipahami.

Ini penting untuk project yang terus berkembang. Sesi 16 membuat arah project, sesi 17 membuat main menu, sesi 18 merapikan fitur menjadi function. Setelah itu, project akan lebih siap untuk ditambah validasi, dokumentasi, dan demo.

Kesalahan umum

Jangan refactor semua sekaligus tanpa tes. Pindahkan satu fitur, jalankan, pastikan benar, baru lanjut fitur berikutnya.

Print dan Return Bisa Bekerja Bersama

Di function cek_budget(), ada dua jenis hasil. Pertama, hasil yang langsung ditampilkan ke user dengan print(). Kedua, ringkasan yang dikirim balik ke main menu dengan return.

Kenapa perlu return? Karena main menu perlu menyimpan ringkasan terakhir. Kalau function hanya mencetak output tanpa mengembalikan apa pun, main menu tidak punya teks ringkasan untuk ditampilkan saat user memilih menu 4.

Inti alurnya

User memilih menu 1 → cek_budget() berjalan → function mengembalikan ringkasan → ringkasan disimpan ke last_summary.

Function Bisa Punya Jalur Aman

Pada fitur target tabungan, pembagian dengan nol harus dihindari. Karena itu, function mengecek dulu apakah jumlah bulan lebih dari 0. Kalau tidak, function memberi pesan dan mengembalikan ringkasan bahwa target belum bisa dihitung.

Ini contoh awal validasi input. Validasi yang lebih lengkap bisa memakai try/except, tetapi untuk sesi ini kamu cukup memahami bahwa function bisa memiliki jalur kondisi agar program tidak menghasilkan hitungan aneh.

Kenapa return tetap dipakai saat input tidak valid?

Agar main menu tetap punya ringkasan yang jelas, bukan nilai kosong yang membingungkan.

Function untuk Keputusan Sederhana

Function keputusan_beli() memakai kondisi untuk memberi rekomendasi. Kalau harga barang masih sesuai sisa uang dan prioritas tidak rendah, barang boleh dipertimbangkan. Kalau tidak, lebih aman ditunda.

Ini bukan aplikasi finansial profesional. Ini latihan membuat logika sederhana dengan data dummy. Yang penting adalah struktur: input dikumpulkan di dalam function, keputusan dibuat, output dicetak, lalu ringkasan dikembalikan.

Catatan etis

Rekomendasi aplikasi belajar tidak boleh dianggap nasihat finansial pribadi. Gunakan sebagai latihan berpikir dan coding.

Main Menu Menjadi Pengarah

Bagian main menu sekarang fokus pada routing: membaca pilihan dan memanggil function yang sesuai. Ini membuat struktur program lebih mudah dibaca dari atas ke bawah.

Kalau nanti ada fitur baru, misalnya “tips hemat mingguan”, kamu bisa membuat function baru tips_hemat(), lalu menambahkan satu cabang menu. Kamu tidak perlu mengacak-acak function lain.

Pola yang dipakai

pilihan → panggil function → simpan ringkasan → kembali ke menu.

Flow Program yang Lebih Terstruktur

Function biasanya didefinisikan dulu di bagian atas file atau notebook. Setelah itu, barulah main program berjalan. Dalam project ini, main program adalah main menu loop.

Ketika user memilih fitur, program memanggil function. Function menjalankan tugasnya, lalu beberapa function mengembalikan ringkasan melalui return. Ringkasan itu disimpan ke last_summary agar bisa ditampilkan lagi.

Urutan penting

Function harus didefinisikan sebelum dipanggil. Kalau kamu memanggil cek_budget() sebelum Python membaca definisinya, program bisa error.

Pseudocode Membantu Menjaga Arah

Ketika memakai function, pseudocode membantu kamu menentukan tugas tiap function. Jangan sampai satu function melakukan terlalu banyak hal sekaligus.

Misalnya, cek_budget() sebaiknya fokus pada fitur cek budget. Jangan tiba-tiba di dalamnya ada logika keluar program atau cetak seluruh main menu. Urusan keluar program tetap milik main menu.

Pertanyaan sebelum coding

Function ini menerima data apa? Melakukan proses apa? Menampilkan output apa? Perlu mengembalikan ringkasan atau tidak?

Menyusun Function Secara Bertahap

Kalau langsung menulis seluruh function, kamu mungkin bingung mulai dari mana. Builder ini menunjukkan urutan sederhana: beri nama function, ambil input, proses data, tampilkan hasil, lalu return ringkasan jika diperlukan.

Nama function sebaiknya spesifik. hitung() terlalu umum, sedangkan hitung_target_tabungan() jauh lebih jelas. Nama yang jelas membuat program terasa seperti daftar instruksi yang bisa dibaca manusia.

Jangan lupa

Kalau function harus dipakai untuk update last_summary, function itu perlu return.

Bedanya Terasa Saat Data Mau Dipakai Lagi

Kalau function hanya memakai print(), hasilnya muncul di layar, tetapi tidak otomatis tersimpan sebagai nilai. Kalau main menu perlu memakai hasil itu lagi, gunakan return.

Dalam project ini, return dipakai untuk mengisi last_summary. Jadi saat user memilih menu 4, program bisa menampilkan ringkasan dari fitur terakhir yang dijalankan.

Contoh

last_summary = cek_budget() artinya hasil return dari cek_budget() disimpan ke variabel last_summary.

Dua Gaya Function

Function yang mengambil input langsung terasa mudah untuk aplikasi CLI. Saat function dipanggil, user langsung diminta mengisi data. Ini sesuai untuk prototype sesi ini.

Namun, function dengan parameter juga penting karena lebih mudah dites. Misalnya, function hitung_sisa(2500000, 2000000) bisa dites tanpa mengetik input manual. Nanti saat project makin matang, kamu bisa memisahkan function input dan function hitung.

Jangan campur terlalu banyak

Untuk sesi ini, pilih pola yang paling mudah kamu jelaskan. Kode yang kamu pahami lebih baik daripada kode yang terlihat canggih tapi tidak kamu kuasai.

Function Membawa Jenis Bug Baru

Saat mulai memakai function, kamu akan bertemu bug yang berbeda dari sesi sebelumnya. Misalnya, lupa tanda kurung saat memanggil function, lupa menulis return, atau mencoba memakai variabel lokal di luar function.

Ini normal. Justru di sinilah kemampuan debugging dari sesi 15 dipakai lagi. Baca error message, cek baris yang disebut, lalu tanyakan: “Apakah function ini sudah dipanggil dengan benar?”

Pola cek cepat

  • Apakah function sudah didefinisikan sebelum dipanggil?
  • Apakah nama function sama persis?
  • Apakah ada tanda kurung saat memanggil?
  • Apakah function perlu return?

Membedakan Output Layar dan Nilai Balik

Bug ini sering mengecoh. Siswa merasa function berhasil karena teks “Sisa uang” muncul di output. Padahal, teks yang muncul karena print() tidak otomatis menjadi nilai yang bisa disimpan.

Kalau kamu menulis last_summary = cek_budget(), Python akan menyimpan nilai yang dikembalikan oleh return. Kalau tidak ada return, nilainya menjadi None.

Debugging hint

Kalau output menampilkan None, cek apakah function yang dipanggil punya return yang sesuai.

Tanda Kurung Itu Penting

Dalam Python, nama function tanpa tanda kurung hanya menunjuk ke function tersebut. Untuk menjalankan isinya, kamu perlu menambahkan tanda kurung: nama_function().

Kalau function punya parameter, datanya masuk di dalam tanda kurung. Contoh: hitung_sisa(2500000, 2000000). Kalau function tidak punya parameter, tanda kurung tetap ditulis kosong.

Ingat

def tampilkan_menu(): membuat function. tampilkan_menu() menjalankan function.

Helper Function untuk Input

Jika sebuah pola dipakai berkali-kali, itu kandidat bagus untuk dibuat function. Misalnya, fitur budget, target tabungan, dan keputusan beli sama-sama meminta input angka. Daripada menulis validasi berulang, kamu bisa membuat helper function input_angka().

Namun, jangan memaksakan semua hal sekaligus. Di sesi ini, yang paling penting adalah memahami struktur function per fitur. Helper validasi bisa menjadi tambahan kalau kamu sudah siap.

Level aman

Minimal: function fitur berjalan dan menu rapi. Bonus: ada helper function untuk input angka agar program lebih tahan error.

Refactor Butuh Ritme

Refactor yang aman dilakukan bertahap. Kalau kamu memindahkan semua kode sekaligus lalu error, kamu akan sulit tahu bagian mana yang menyebabkan masalah.

Mulai dari function paling sederhana, misalnya tampilkan_menu(). Setelah itu pindahkan cek_budget(). Jalankan. Kalau sudah aman, lanjut ke hitung_target_tabungan() dan keputusan_beli().

Aturan kecil

Satu perubahan besar sebaiknya diikuti satu test. Jangan menumpuk perubahan tanpa mengecek output.

Readable Code Itu Penting

Kode yang baik bukan hanya kode yang bisa jalan. Kode yang baik juga bisa dibaca oleh orang lain, termasuk guru, teman, dan kamu sendiri saat membuka notebook beberapa hari kemudian.

Nama seperti fitur1() mungkin cepat ditulis, tetapi tidak memberi informasi. Nama seperti cek_budget() langsung memberi gambaran tugas function.

Kebiasaan developer

Nama yang jelas mengurangi kebutuhan komentar berlebihan, karena struktur kode sudah berbicara.

Komentar untuk Struktur Function

Komentar berguna saat ada alasan yang tidak langsung terlihat dari kode. Misalnya, kenapa function perlu return, atau kenapa input bulan tidak boleh 0.

Namun, komentar tidak perlu mengulang baris kode. Kalau nama function sudah jelas, komentar bisa dipakai untuk menjelaskan tujuan yang lebih besar.

Untuk notebook project

Tambahkan komentar singkat di atas function penting, terutama function yang mengembalikan ringkasan ke main menu.

Data Dummy Tetap Jadi Aturan

Project ini bertema finansial, tetapi bukan berarti kamu harus memakai data asli. Justru untuk latihan coding, data dummy lebih aman dan lebih mudah dites.

Kalau ingin bertanya ke AI tentang bug, cukup kirim potongan kode, error message, dan data contoh. Jangan memasukkan password, nomor rekening, alamat rumah, atau detail finansial pribadi.

Pengingat

Aplikasi yang kamu buat adalah prototype belajar. Jaga privasi diri sendiri dan orang lain.

Deck Mengikuti Perkembangan Prototype

Setelah sesi 18, kamu bisa menjelaskan bahwa prototype sudah lebih modular. Artinya, fitur-fitur utama dipisah menjadi function sehingga lebih mudah dibaca dan dikembangkan.

Di pitch deck, tidak perlu menampilkan semua kode panjang. Cukup jelaskan struktur, fitur utama, alur demo, dan test case yang membuktikan aplikasi berjalan.

Contoh narasi demo

“Prototype kami memakai main menu loop. Setiap pilihan memanggil function berbeda, lalu hasil terakhir disimpan agar user bisa melihat ringkasan.”

Quality Check

Sebelum submit, jalankan notebook dari atas. Ini penting karena function harus didefinisikan sebelum dipanggil. Kalau kamu menjalankan cell secara acak, kadang output terlihat aman padahal urutan notebook belum rapi.

Pastikan juga test case tertulis atau terlihat dari output. Guru akan lebih mudah melihat bahwa kamu tidak hanya membuat kode, tetapi juga membuktikan bahwa alurnya berjalan.

Hal yang sering terlewat

Function sudah dibuat, tapi main menu masih memakai kode lama. Pastikan main menu benar-benar memanggil function yang baru.

Refleksi Sesi 18

Kalau kamu bisa menjelaskan alasan memakai function, berarti kamu sudah naik satu level dalam menulis program. Kamu tidak hanya membuat program berjalan, tetapi juga mulai memikirkan struktur.

Refleksi kecil membantu kamu melihat bagian mana yang sudah kuat dan bagian mana yang perlu diperbaiki. Misalnya, kamu mungkin sudah bisa membuat function, tetapi masih sering lupa return atau tanda kurung saat memanggil function.

Kalimat refleksi

“Hari ini aku memindahkan fitur ____ menjadi function ____. Function ini mengembalikan ____ agar bisa dipakai oleh main menu.”

Rangkuman

Function membantu kamu memecah program besar menjadi bagian kecil yang punya tugas jelas. Dalam project CLI, function membuat main menu lebih bersih karena detail fitur tidak semuanya ditaruh di dalam loop.

Ingat pola sesi ini: buat function → panggil dari menu → return ringkasan jika perlu → test per fitur → test alur menu. Pola ini akan sangat berguna saat project semakin besar.
