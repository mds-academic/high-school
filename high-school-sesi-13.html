Project yang Akan Dibuat

Di sesi 11 kamu sudah belajar list, lalu di sesi 12 kamu memakai dictionary. Sesi ini menggabungkan keduanya dengan loop. Ini mulai terasa seperti aplikasi kecil yang punya alur kerja nyata.

Kasir mini membutuhkan tiga bagian utama: keranjang berisi barang yang dibeli, data harga untuk mencari harga setiap barang, dan loop untuk membaca barang satu per satu sampai totalnya selesai dihitung.

Mindset sesi ini

Jangan hanya mengejar hasil total. Fokus juga pada cara program “berpikir”: ambil satu item → cek harga → tambahkan ke total → ulangi sampai keranjang habis.

Alur Belajar Sesi Ini

Sesi ini adalah jembatan penting sebelum masuk ke function di sesi berikutnya. Kamu mulai melihat bahwa struktur data tidak berdiri sendiri. List, dictionary, dan loop bisa bekerja bareng untuk menyelesaikan masalah yang lebih realistis.

  • List menyimpan urutan barang yang masuk ke keranjang.
  • Dictionary menyimpan harga setiap barang.
  • Loop membuat program tidak perlu menulis kode berulang untuk setiap barang.

Kenapa ini berguna?

Kalau keranjang berisi 3 item, loop bekerja 3 kali. Kalau nanti keranjang berisi 20 item, konsepnya tetap sama. Program tidak perlu ditulis ulang 20 kali.

Persiapan Coding

Program kasir mini akan lebih mudah dipahami kalau kamu menjalankan kode beberapa kali sambil mengubah isi keranjang. Jadi, pastikan notebook atau editor bisa dipakai untuk run cell dengan lancar.

Data yang dipakai di sesi ini adalah data simulasi: roti, air, pensil, buku, dan barang sederhana lainnya. Jangan memakai data transaksi nyata, nama pembeli asli, kartu pembayaran, PIN, atau informasi sensitif lain.

Catatan keamanan

Kode latihan kadang dibagikan ke guru atau teman. Karena itu, biasakan hanya memakai data dummy untuk semua project latihan.

List vs Dictionary

List dan dictionary sama-sama bisa menyimpan banyak data, tetapi tugasnya berbeda. List cocok untuk daftar item: barang pertama, kedua, ketiga, dan seterusnya. Dictionary cocok untuk data berpasangan: nama barang dipasangkan dengan harga.

Di sistem kasir mini, list berperan seperti isi keranjang. Dictionary berperan seperti daftar harga toko. Program akan mengambil setiap item dari list, lalu memakai item itu sebagai key untuk mencari harga di dictionary.

Kalimat penting

harga_barang[item] berarti: “ambil harga dari dictionary berdasarkan nama item yang sedang dibaca loop.”

Dari Toko ke Program

Bayangkan kasir sungguhan. Ia tidak langsung tahu total akhir. Ia membaca barang pertama, mengecek harga, menambahkan ke total, lalu lanjut ke barang berikutnya.

Program kita akan meniru proses itu. Bedanya, kasir manusia membaca barcode atau label. Program Python membaca data dari list dan dictionary.

Proses yang ditiru

Ambil barang → lihat harga → tambahkan ke total → ulangi sampai semua barang selesai.

Kenapa Hitung Manual Dulu?

Hitung manual membantu kamu tahu hasil yang seharusnya. Saat program selesai dibuat, kamu bisa membandingkan output program dengan hitungan manual.

Ini adalah kebiasaan testing yang bagus. Programmer sering membuat contoh kecil terlebih dahulu agar mudah mengecek apakah program bekerja sesuai logika.

Expected output

Untuk keranjang ["roti", "air", "pensil"], total yang benar adalah Rp18.000. Kalau program menampilkan angka lain, berarti ada bug yang perlu dicek.

Membaca List Keranjang

List keranjang berisi nama barang yang dibeli. Setiap nama barang ditulis sebagai string karena kita tidak menghitung nama barang sebagai angka.

Urutan dalam list bisa dibaca dari kiri ke kanan. Pada contoh ["roti", "air", "pensil"], loop akan membaca roti dulu, lalu air, lalu pensil.

Kesalahan umum

Jangan menulis nama barang tanpa tanda kutip. roti tanpa kutip dianggap nama variabel, sedangkan "roti" adalah teks.

Membaca Dictionary Harga

Dictionary harga_barang menyimpan harga dengan pola "nama_barang": harga. Nama barang menjadi key. Harga menjadi value.

Harga disimpan sebagai angka integer, bukan string, karena nanti akan dijumlahkan. Kalau harga ditulis "10000" sebagai teks, operasi penjumlahan bisa jadi bermasalah.

Contoh akses

harga_barang["roti"] menghasilkan 10000.

Exact Match pada Dictionary

Ketika loop membaca item, isi variabel itu dipakai untuk mencari key di dictionary. Kalau item berisi "roti", Python mencari key "roti".

Masalah muncul kalau tulisan di list tidak sama persis dengan key dictionary. "Roti" dan "roti" dianggap berbeda karena kapitalnya tidak sama. Jika key tidak ditemukan, program bisa berhenti dengan KeyError.

Tips

Gunakan nama barang yang konsisten: semua huruf kecil, tanpa spasi tambahan, dan sesuai dengan key dictionary.

Cara Membaca for Loop

Baris for item in keranjang: berarti: untuk setiap barang di dalam list keranjang, jalankan blok kode yang menjorok ke dalam.

Variabel item akan berubah otomatis di setiap putaran. Putaran pertama bisa berisi "roti", putaran kedua "air", dan putaran ketiga "pensil".

Indentasi penting

Baris yang menjadi bagian dari loop harus menjorok ke dalam. Kalau indentasinya salah, Python bisa error atau hasilnya tidak sesuai.

Kenapa Total Harus Diinisialisasi?

Variabel total harus dibuat sebelum loop dimulai. Jika tidak, Python tidak tahu nilai awal yang harus ditambah.

Kita memakai total = 0 karena belum ada barang yang dihitung. Setelah itu, setiap putaran loop menambahkan harga barang ke variabel total.

Pola akumulasi

total += harga adalah versi singkat dari total = total + harga. Artinya, total lama ditambah harga baru, lalu disimpan kembali sebagai total terbaru.

Membaca Trace Table

Trace table membantu kamu membongkar proses program langkah demi langkah. Ini berguna saat output akhir salah, karena kamu bisa mencari di putaran mana total mulai melenceng.

Pada putaran pertama, total dari 0 berubah menjadi 10.000. Pada putaran kedua, 5.000 ditambahkan sehingga total menjadi 15.000. Pada putaran ketiga, 3.000 ditambahkan sehingga total akhir menjadi 18.000.

Debugging tip

Kalau total akhir tidak sesuai, tambahkan print() di dalam loop untuk melihat nilai item, harga, dan total di setiap putaran.

Alur Sebelum Kode

Flowchart ini membantu kamu melihat struktur program sebelum membaca kode lengkap. Program selalu mulai dari data awal: dictionary harga dan list keranjang.

Setelah data siap, loop mulai bekerja. Loop mengambil satu item, mencari harga, menambahkan ke total, lalu lanjut ke item berikutnya. Setelah semua item selesai, program mencetak total belanja.

Kenapa alur ini penting?

Kalau kamu tahu alur program, kode panjang akan terasa lebih mudah dibaca karena setiap bagian punya tujuan yang jelas.

Data Dasar Project

Kode ini belum menghitung total. Tujuannya hanya memastikan dua data utama sudah benar: dictionary harga dan list keranjang.

Perhatikan bedanya: harga_barang memakai {} karena berisi pasangan nama dan harga. keranjang memakai [] karena berisi daftar item.

Hal yang perlu dicek

Pastikan setiap item di list keranjang punya pasangan harga di dictionary. Kalau tidak, saat loop mencoba mengambil harga, program bisa terkena KeyError.

Loop dan Akumulasi Total

Program ini menunjukkan proses akumulasi. total dimulai dari 0, lalu bertambah setiap kali loop membaca item baru.

Baris harga = harga_barang[item] mengambil harga berdasarkan item yang sedang dibaca. Baris total += harga menambahkan harga itu ke total sementara.

Kenapa outputnya per langkah?

Print di dalam loop membantu melihat proses, bukan hanya hasil akhir. Ini sangat membantu saat debugging.

Mengapa Perlu Format Output?

Program yang benar belum tentu nyaman dibaca. Kasir mini harus menampilkan harga dan total dengan jelas agar user tidak bingung.

Di Python, format {total:,} menambahkan pemisah ribuan gaya internasional. Untuk materi kelas, boleh dibaca sebagai pemisah ribuan. Nantinya, kamu bisa membuat fungsi format rupiah yang lebih Indonesia.

Clean output

Output seperti Rp18,000 lebih mudah dibaca daripada 18000 tanpa keterangan.

Testing sederhana

Testing dengan Keranjang Berbeda

Testing tidak cukup sekali. Kamu perlu mencoba beberapa komposisi keranjang untuk memastikan loop menghitung sesuai isi list.

Case 1 mengecek contoh utama. Case 2 mengecek barang lain. Case 3 mengecek barang yang sama muncul lebih dari sekali. Edge case mengecek apa yang terjadi jika ada barang yang belum punya harga.

Pelajaran dari edge case

Program dasar akan error jika item di keranjang tidak ada di dictionary harga. Ini bukan kegagalan; ini petunjuk bahwa program butuh validasi atau data yang lebih lengkap.

Membaca KeyError di Sistem Kasir

KeyError: 'kopi' berarti Python mencoba mencari key "kopi" di dictionary, tetapi key itu belum ada.

Ada dua cara memperbaiki tergantung tujuan. Kalau kopi memang barang yang dijual, tambahkan harga kopi ke dictionary. Kalau kopi tidak seharusnya ada di keranjang, hapus atau ganti item tersebut dari list.

Jangan asal menambal

Jangan mengganti semua kode hanya karena satu error. Baca pesan error, cari key yang bermasalah, lalu cek data dictionary dan list.

Kenapa total = 0 Harus di Luar Loop?

Jika total = 0 ditaruh di dalam loop, total akan direset pada setiap putaran. Akibatnya, program tidak benar-benar mengumpulkan jumlah dari semua barang.

Total harus dibuat sebelum loop. Setelah itu, di dalam loop hanya ada proses menambahkan harga ke total. Jadi nilai total terus bertambah, bukan kembali ke 0.

Pola benar

total = 0 di luar loop, lalu total += harga di dalam loop.

Latihan Membaca Kode

Loop membaca dua item: roti dan air. Harga roti adalah 10.000, harga air adalah 5.000. Total dimulai dari 0, lalu menjadi 10.000, lalu menjadi 15.000.

Karena kedua key ada di dictionary, tidak ada KeyError. Output akhirnya adalah 15000.

Skill yang dilatih

Membaca kode tanpa langsung menjalankan program membantu kamu memahami alur, bukan hanya bergantung pada tombol Run.

Challenge ini menggabungkan penghitungan total dengan kondisi if. Program mengecek apakah total sudah mencapai batas diskon.

Jika total minimal Rp25.000, diskon 10% dihitung dari subtotal. Jika belum, total bayar sama dengan subtotal. Ini contoh sederhana bagaimana aturan bisnis bisa diterjemahkan ke kode.

Catatan

Diskon di sini hanya simulasi. Fokusnya adalah memahami kondisi dan penghitungan, bukan membuat sistem promo sungguhan.

Menggunakan append untuk Keranjang

Pada aplikasi nyata, keranjang tidak selalu langsung penuh sejak awal. Item bisa ditambahkan satu per satu saat pembeli memilih barang.

Dengan append(), list keranjang bisa dibuat kosong dulu, lalu diisi bertahap. Setelah itu, loop tetap bekerja dengan cara yang sama: membaca semua item dan menjumlahkan harga.

Konsep penting

Selama bentuk akhirnya tetap list berisi nama barang yang cocok dengan dictionary harga, loop bisa menghitungnya.

Output yang Ramah User

Output program adalah bagian yang dilihat user. Jika output hanya angka, user mungkin bingung angka itu berarti apa. Karena itu, struk perlu label dan format yang jelas.

Debugging Sistem Kasir

Bug di sesi ini biasanya tidak jauh dari hubungan list, dictionary, dan loop. Karena tiga konsep ini bekerja bersama, satu data yang tidak cocok bisa membuat program gagal.

Gunakan pola debugging: baca error message, cari baris kode yang ditunjuk, cek data yang sedang dipakai, lalu test ulang dengan contoh kecil.

Urutan cek cepat

  1. Apakah nama item di list sama dengan key dictionary?
  2. Apakah indentasi loop benar?
  3. Apakah total dimulai dari 0 sebelum loop?
  4. Apakah harga ditulis sebagai angka?

Kode yang Mudah Dibaca

Kode yang benar tetap bisa sulit dipahami jika nama variabelnya terlalu pendek atau tidak jelas. Saat project mulai punya beberapa struktur data, nama variabel yang jelas sangat membantu.

Gunakan nama seperti harga_barang, keranjang, total, dan harga. Nama-nama ini memberi petunjuk langsung tentang fungsi setiap variabel.

Prinsip sederhana

Kode yang mudah dibaca hari ini akan lebih mudah diperbaiki besok.

Checklist Kualitas Project

Checklist ini bukan hanya untuk memastikan program jalan. Gunakan untuk memastikan struktur data, loop, output, dan keamanan data sudah sesuai.

Kalau ada satu item yang belum selesai, kembali ke slide terkait. Misalnya total salah, cek slide total dan trace table. Jika ada KeyError, cek kecocokan item list dan key dictionary.

Standar minimum

Program membaca item dari list, mengambil harga dari dictionary, dan menjumlahkan total dengan loop.

Rangkuman Sesi 13

Sistem kasir mini adalah contoh bagus untuk melihat bagaimana beberapa konsep Python bekerja bareng. List menyimpan barang, dictionary menyimpan harga, loop mengulang proses, dan variabel total menyimpan hasil penjumlahan.

Konsep ini akan kepakai lagi saat programmu makin besar. Nanti, function bisa membantu membungkus proses hitung total agar lebih rapi dan bisa dipakai ulang.
