Percobaan Tak Terbatas dan Brute-Force

Jika sistem mengizinkan input PIN tanpa batas, seseorang atau program otomatis dapat mencoba kombinasi berulang kali sampai menemukan nilai yang benar. Pola mencoba banyak kombinasi seperti ini disebut brute-force.

Fokus sesi

Kita mempelajari risiko dan logika pertahanannya, bukan cara melakukan serangan. Tujuannya adalah memahami mengapa batas percobaan penting dalam desain sistem.

Struktur Dasar while

Bentuk umum while adalah while kondisi:. Python mengecek kondisi sebelum setiap iterasi. Selama hasilnya True, seluruh baris yang terindentasi di bawahnya dijalankan.

Setelah blok selesai, alur kembali ke baris while dan kondisi dicek lagi. Jika suatu saat kondisi menjadi False, loop selesai dan Python melanjutkan ke baris sesudah loop.

Perhatikan indentasi

Seperti pada if dan for, tanda titik dua membuka blok. Baris yang menjadi bagian dari loop harus menjorok ke kanan secara konsisten.

while True dan Infinite Loop

True adalah nilai Boolean yang selalu benar. Jadi, while True: berarti “terus ulangi blok ini”. Pola ini berguna untuk program yang menunggu input user sampai kondisi tertentu terjadi.

Namun, karena kondisinya tidak pernah berubah menjadi False, program membutuhkan jalan keluar yang jelas. Pada Brankas Terkunci, jalan keluarnya adalah break ketika PIN benar dan, pada challenge, break lain ketika batas percobaan tercapai.

Tanpa jalan keluar

while True tanpa mekanisme berhenti dapat menghasilkan infinite loop: program terus berulang dan tidak pernah mencapai kode setelah loop.

Fungsi break

break menghentikan loop terdekat secara langsung. Python tidak menunggu kondisi while menjadi False; eksekusi langsung keluar dari loop dan berlanjut ke baris setelah blok pengulangan.

Karena itu, posisi break sangat penting. Pada project ini, break untuk membuka brankas harus berada di dalam cabang if input_pin == PIN_DUMMY:. Jika indentasinya salah, program bisa berhenti walaupun PIN salah.

Bayangkan sebagai pintu darurat

Loop boleh terus berputar, tetapi saat kondisi target tercapai, break membuka pintu keluar dan proses pengulangan selesai.

Membaca Alur per Iterasi

Trace membantu kita mengikuti program langkah demi langkah. Misalnya input yang diberikan adalah 0000, lalu 9999, lalu 1211. Pada iterasi pertama dan kedua, perbandingan menghasilkan False, sehingga loop kembali ke atas dan meminta input baru.

Pada iterasi ketiga, input_pin == PIN_DUMMY menjadi True. Program menampilkan pesan berhasil, menjalankan break, lalu keluar dari while.

Kenapa trace penting?

Kalau output program berbeda dari prediksi, kamu bisa mencari pada iterasi mana state atau jalur kondisinya mulai melenceng.

Kenapa PIN Lebih Tepat sebagai string?

PIN adalah kode identifikasi, bukan angka untuk dihitung. Karena itu, PIN lebih aman dimodelkan sebagai teks: PIN_DUMMY = "1211".

String juga mempertahankan nol di depan. PIN "0121" tetap memiliki empat karakter, sedangkan jika diperlakukan sebagai integer, nilai tersebut secara numerik menjadi 121 dan format aslinya hilang.

Yang kita lakukan

input() menghasilkan string, sehingga perbandingan bisa langsung dilakukan dengan == terhadap PIN dummy yang juga berupa string.

State Counter

Counter menyimpan jumlah kesalahan yang sudah terjadi. Nilai awalnya percobaan = 0 karena sebelum user memasukkan PIN, belum ada percobaan salah.

Ketika PIN salah, baris percobaan = percobaan + 1 mengambil nilai lama lalu menambah satu. Nilai ini harus bertahan dari satu iterasi ke iterasi berikutnya: 0 → 1 → 2 → 3.

Jangan reset di dalam loop

Jika percobaan = 0 diletakkan di dalam while, setiap putaran nilainya kembali ke nol. Akibatnya, batas tiga kali tidak pernah benar-benar tercapai.

Ini disebut state

State adalah informasi tentang kondisi program saat ini yang perlu dibawa ke langkah berikutnya. Counter adalah contoh state sederhana.

Dua Kondisi Terminal

Versi challenge memiliki dua alasan untuk keluar dari loop. Pertama, PIN benar: program membuka brankas dan menghentikan pengulangan. Kedua, kesalahan sudah mencapai tiga kali: program memblokir akses sementara lalu berhenti.

Dua kondisi ini sama-sama menjalankan break, tetapi berada pada jalur logika yang berbeda. Karena itu, susunan if, else, counter, dan pengecekan batas harus dibaca sesuai urutan.

Urutan saat PIN salah

Tambah counter → tampilkan nomor percobaan → cek apakah counter sudah ≥ 3 → jika ya, blokir dan break; jika belum, kembali ke atas.

Bug Reading Code: break Salah Posisi

Bug ini tidak selalu menghasilkan pesan error. Program bisa tetap berjalan, tetapi perilakunya salah. Jika break ditulis sejajar dengan if di dalam while, baris itu akan dijalankan pada setiap iterasi, bukan hanya ketika PIN benar.

Akibatnya, program berhenti setelah satu input saja. Ini disebut logic error: sintaks sah, tetapi logikanya tidak sesuai tujuan.

Cara debug

Baca indentasi seperti struktur bertingkat. Tanyakan: “Kondisi apa yang seharusnya mengaktifkan baris ini?” Lalu pastikan posisi baris berada di dalam blok kondisi tersebut.

Latihan Pola while True + break

Latihan dengan kata stop memisahkan konsep loop dari konteks PIN. Program terus meminta teks selama user belum mengetik kata yang menjadi sinyal berhenti.

Strukturnya sama dengan project utama: input() berada di dalam loop supaya mendapat nilai baru setiap iterasi, if memeriksa target, lalu break menghentikan loop saat target ditemukan.

Coba eksperimen

Masukkan beberapa baris input sebelum stop. Perhatikan berapa kali output muncul dan pada titik mana program tidak membaca input berikutnya lagi.

Prediksi sebelum Menekan Run

Kebiasaan developer yang baik adalah menentukan expected output lebih dulu. Untuk input 0000, 9999, lalu 1211, kita mengharapkan dua pesan PIN salah dan satu pesan brankas terbuka.

Jika hasil aktual berbeda, prediksi tadi menjadi alat debugging. Misalnya program berhenti setelah 0000, kemungkinan besar break berada di posisi yang salah. Jika program tidak pernah berhenti setelah 1211, cek kondisi perbandingan atau posisi break.

Blueprint Project Brankas Terkunci

Project dapat dipecah menjadi pola Input–Process–Output. Input: PIN yang diketik user. Process: loop, perbandingan string, counter kesalahan, dan pengecekan batas. Output: pesan berhasil, pesan PIN salah, atau pesan akses diblokir.

Bangun program secara bertahap. Pertama buat PIN dummy dan loop dasar. Setelah itu pastikan break bekerja. Baru tambahkan counter dan batas tiga percobaan. Cara ini membuat sumber bug lebih mudah ditemukan.

Checkpoint

Variabel yang Harus Ada sebelum Loop

PIN dummy perlu tersedia setiap kali input dibandingkan. Counter juga perlu mempertahankan nilainya. Karena itu, keduanya dibuat sebelum while True.

Jika memakai konstanta batas seperti MAX_PERCOBAAN = 3, letakkan bersama variabel awal agar aturan program mudah dibaca dan tidak tersebar di banyak baris.

State awal

PIN_DUMMY = "1211"
percobaan = 0
MAX_PERCOBAAN = 3

Kenapa input() Harus di Dalam Loop?

Tujuan loop adalah memberi kesempatan user memasukkan nilai baru setiap putaran. Karena itu, input_pin = input(...) harus dieksekusi lagi pada setiap iterasi.

Jika input() diletakkan sebelum while, variabel input_pin hanya diisi sekali. Loop kemudian membandingkan nilai yang sama berulang-ulang, sehingga user tidak punya kesempatan memperbaiki PIN.

Urutan satu iterasi

Minta input → bandingkan → tentukan aksi → bila belum selesai, kembali meminta input baru.

Menambah Counter dan Batas

Counter hanya bertambah ketika PIN salah. Itu sebabnya baris penambahan ditempatkan di dalam cabang else, bukan pada jalur PIN benar.

Setelah nilai bertambah, program mengecek percobaan >= MAX_PERCOBAAN. Operator >= dipakai agar saat nilai tepat 3, kondisi langsung dianggap benar dan akses dihentikan.

Dua bug umum

Counter dibuat ulang di dalam loop → nilainya tidak pernah mencapai 3. break pengecekan batas salah indentasi → program bisa berhenti terlalu cepat atau justru tidak berhenti.

Untuk setiap case, tulis dulu input dan hasil yang diharapkan. Setelah Run, bandingkan output aktual dengan ekspektasi.

Trace Table dan Perubahan State

Trace table mencatat apa yang terjadi pada setiap iterasi: input yang masuk, apakah perbandingan PIN menghasilkan True/False, nilai counter setelah proses, dan aksi berikutnya.

Pada PIN salah, counter bertambah. Pada PIN benar, program seharusnya keluar sebelum menambah counter. Hubungan ini membantu kamu mengecek apakah baris berada di cabang yang tepat.

Contoh pola

Iterasi 1: salah → counter 1 → ulang. Iterasi 2: salah → counter 2 → ulang. Iterasi 3: benar → buka → break.

Debug: Program Berhenti Terlalu Cepat

Jika program berhenti setelah input pertama walaupun PIN salah, cek terlebih dahulu posisi break. Bug ini sering terjadi karena indentasi membuat break berada di luar cabang yang seharusnya.

Jangan langsung mengganti seluruh program. Bandingkan struktur indentasi dengan blueprint: break sukses hanya boleh dijalankan ketika kondisi PIN benar.

Debug satu hal dulu

Perbaiki posisi break, Run ulang dengan test case salah-lalu-benar, lalu baru lanjut mengecek bagian lain.

Debug: Counter Tidak Pernah Naik

Gejalanya biasanya pesan selalu menunjukkan percobaan pertama, atau batas tiga kali tidak pernah tercapai. Penyebab umum: percobaan = 0 berada di dalam loop.

Inisialisasi seharusnya terjadi satu kali sebelum pengulangan dimulai. Setelah itu, loop hanya mengubah nilainya saat PIN salah. Dengan begitu, state bergerak 0 → 1 → 2 → 3.

Lokasi baris memengaruhi perilaku

Baris yang sama dapat menghasilkan program berbeda hanya karena ditempatkan sebelum loop atau di dalam loop.

Debug: Infinite Loop

while True memang dirancang terus berjalan. Jika tidak ada break yang bisa dicapai, program dapat mengulang tanpa akhir. Pada program input interaktif, kamu mungkin melihat prompt terus muncul atau proses tidak pernah sampai ke bagian setelah loop.

Untuk mencari penyebabnya, cek dua hal: apakah kondisi target benar-benar bisa menjadi True, dan apakah break berada di jalur yang dapat dieksekusi.

Simulator slide

Editor di slide memiliki batas keselamatan agar halaman tidak hang. Di Python/Colab asli, hentikan eksekusi jika loop tidak terkendali, lalu perbaiki logikanya sebelum Run lagi.

Keamanan Tidak Berhenti pada “3 Kali”

Batas percobaan adalah lapisan dasar untuk memperkecil kesempatan mencoba PIN berkali-kali. Modul juga mengenalkan contoh mekanisme yang dipakai sistem profesional, seperti cooldown time setelah beberapa kegagalan dan Two-Factor Authentication (2FA).

Artinya, autentikasi yang baik biasanya memakai beberapa lapisan, bukan hanya satu kondisi if. Project kita sengaja disederhanakan agar fokus pada logika loop dan literasi digital.

Yang perlu dipahami

Developer harus memikirkan bukan hanya “fitur bekerja”, tetapi juga “apa yang terjadi jika user atau program mencoba sistem berkali-kali?”.

Extension Challenge: Sisa Percobaan

Setelah counter berfungsi, kamu bisa membuat feedback yang lebih informatif. Nilai sisa kesempatan dapat dihitung dengan MAX_PERCOBAAN - percobaan.

Pesan seperti “Percobaan ke-2 dari 3” atau “Sisa 1 kesempatan” membantu user memahami state sistem. Namun, logika utamanya tetap sama: saat counter mencapai batas, tampilkan pesan blokir lalu break.

Urutan yang aman

Tambah counter → hitung/tampilkan sisa → cek batas → bila batas tercapai, blokir dan keluar.

Checklist Output Minimum

Project inti dianggap berhasil jika loop benar-benar meminta input berulang, PIN benar dapat menghentikan loop, dan versi challenge mampu menghentikan sistem setelah batas kesalahan tercapai.

Selain “tidak error”, cek juga perilaku. Program yang berjalan tanpa SyntaxError masih bisa memiliki logic error, misalnya counter reset atau break selalu dieksekusi.

Sebelum submit

Run minimal tiga test case: benar langsung, salah lalu benar, dan tiga kali salah. Pastikan output sesuai dengan expected result.

Refleksi sebagai Developer

Coba jawab dengan alasan, bukan hanya definisi. Misalnya: “PIN memakai string karena merupakan identifier dan bisa memiliki nol di depan,” bukan sekadar “karena PIN adalah teks”.
