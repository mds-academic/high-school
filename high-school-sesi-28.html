Enkripsi dan Hashing Tidak Sama

Enkripsi (contoh Caesar)

Pesan diubah dan dapat dikembalikan dengan kunci yang tepat.

Hashing

Data diolah menjadi digest yang tidak dirancang untuk didekripsi.

Contoh penggunaan

Enkripsi melindungi isi saat perlu dibaca kembali; hashing password membantu memverifikasi tanpa menyimpan bentuk asli.

Import Modul hashlib

import hashlib

password_dummy = "KoperasiJuara2026!"
byte_data = password_dummy.encode("utf-8")
print(type(byte_data))  # <class 'bytes'>

Fokus sintaks

encode("utf-8") mengubah string menjadi bytes, bukan menjadi hash.

Menghasilkan Digest SHA-256

import hashlib

teks = "contoh123"
byte_data = teks.encode("utf-8")
hash_obj = hashlib.sha256(byte_data)
hash_hex = hash_obj.hexdigest()
print(hash_hex)
print(len(hash_hex))  # 64

Output yang diharapkan

hash_hex adalah string heksadesimal sepanjang 64 karakter.

Bungkus Menjadi Satu Function

def buat_hash_sha256(teks_biasa):
    data_bytes = teks_biasa.encode("utf-8")
    return hashlib.sha256(data_bytes).hexdigest()

print(len(buat_hash_sha256("sandi_dummy")))  # 64

Checklist kode

Fungsi menerima string, mengubahnya ke bytes, kemudian mengembalikan string hasil hexdigest.

Kenapa password perlu dilindungi?

Bayangkan aplikasi koperasi menaruh password asli dalam tabel database. Jika seseorang memperoleh salinan tabel tersebut, ia bisa membaca seluruh sandi tanpa perlu memecahkan kode apa pun. Ini berbahaya karena pengguna kadang memakai kata sandi serupa di beberapa layanan.

Dalam simulasi yang kita buat, database hanya berisi username dan nilai hash. Artinya teks sandi asli tidak dicatat ke dictionary. Tetap ingat: hash saja bukan jaminan keamanan. Password lemah bisa ditebak menggunakan percobaan dan daftar kata sandi. Sistem nyata membutuhkan salt yang unik, algoritma hashing password khusus, pembatasan percobaan login, dan kontrol keamanan lain.

Jangan menyebut hash sebagai enkripsi satu arah

Keduanya sama-sama dapat menghasilkan keluaran yang tidak mudah dibaca manusia, tetapi tujuan matematisnya berbeda. Enkripsi memungkinkan penerima yang berwenang mengembalikan ciphertext ke plaintext dengan mekanisme dekripsi. Hashing menghasilkan nilai ringkas dengan panjang tetap; tidak tersedia fungsi dekripsi untuk memperoleh data asli.

Dalam simulasi autentikasi, kita memverifikasi dengan menghitung hash dari password percobaan lalu membandingkannya dengan hash tersimpan. Dengan kata lain, program tidak perlu memulihkan hash menjadi password semula.

Melihat alur data yang sesungguhnya

Python menyimpan kata sebagai objek string. Fungsi hashlib.sha256() bekerja dengan data berupa bytes, jadi string perlu lebih dulu di-encode. SHA-256 kemudian menghitung digest 256-bit. Ketika dipresentasikan dalam format heksadesimal, setiap byte ditulis sebagai dua digit hex sehingga hasilnya 64 karakter.

Hash bukan rangkaian huruf yang dapat dibaca terbalik untuk memperoleh password. Ia merupakan hasil proses matematika. Jika ingin memverifikasi input baru, lakukan proses yang sama ke input tersebut dan bandingkan hasilnya.

Mengapa hasil hash bisa diperiksa ulang?

Sifat deterministik berarti input yang persis sama menghasilkan output SHA-256 yang sama, selama byte inputnya identik. Inilah alasan sistem bisa mencocokkan password saat login. Sifat avalanche berarti perubahan kecil pada input—misalnya huruf K menjadi k atau tambahan satu spasi—menghasilkan digest yang umumnya sangat berbeda.

Namun, efek avalanche tidak otomatis membuat password mudah ditebak menjadi aman. Jika password sederhana, penyerang dapat menghitung hash dari banyak tebakan dan mencari kecocokan. Karena itu kata sandi sebenarnya membutuhkan metode penyimpanan yang lebih kuat daripada SHA-256 polos.

Kenapa perlu encode()

Ketika kamu menulis "KoperasiJuara2026!", Python menganggapnya string. Fungsi SHA-256 dari hashlib membutuhkan bytes. Memanggil .encode("utf-8") mengubah teks menjadi representasi bytes yang dapat diproses. Parameter UTF-8 adalah format encoding teks, bukan algoritma hashing.

Kesalahan umum adalah memasukkan string langsung ke hashlib.sha256(). Python akan mengembalikan TypeError karena tipe datanya salah. Sebelum menjalankan fungsi hash, cek bahwa konversi bytes sudah dilakukan.

Mengapa ada .hexdigest()?

Pemanggilan hashlib.sha256(byte_data) membuat objek hash. Agar nilainya mudah ditampilkan dan disimpan dalam dictionary, panggil .hexdigest(). Method ini memberikan representasi teks dari digest dalam format heksadesimal, yaitu kombinasi karakter 0–9 dan a–f.

Jumlah karakternya selalu 64 untuk SHA-256, meskipun panjang input berbeda. Panjang tetap ini adalah sifat output hash, bukan bukti bahwa semua password memiliki kekuatan yang sama.

Kenapa fungsi memudahkan registrasi dan login?

Dengan satu fungsi buat_hash_sha256(), bagian registrasi dan login dapat menggunakan proses yang sama. Kamu tidak perlu mengulang encode() dan sha256() di setiap tempat. Hal ini juga mengurangi risiko kedua proses menggunakan aturan hashing yang berbeda.

Pada Student Project, fungsi ini masih mempunyai bagian yang harus kamu lengkapi. Gunakan contoh di slide untuk memahami alurnya, lalu tulis sesuai kerangka TODO notebook. Jangan memakai password asli saat mencoba.

Mencermati sifat deterministik dan avalanche

Setiap pilihan menghasilkan string SHA-256 sepanjang 64 karakter, tetapi nilai hash akan berbeda jika salah satu karakter input berubah. Coba pilihan pertama dua kali: hasilnya tetap sama. Kemudian pilih versi dengan huruf kecil di awal atau versi yang memiliki spasi tambahan; digest-nya berubah.

Pada notebook, siswa melakukan eksperimen yang sama menggunakan fungsi buat_hash_sha256(). Perhatikan bahwa spasi adalah karakter yang ikut di-hash. Tidak ada penyesuaian otomatis untuk huruf kapital atau spasi, kecuali kamu sendiri menulis aturan normalisasi—dan untuk password, normalisasi sembarangan justru dapat mengubah makna sandi pengguna.

Penyimpanan sementara di dictionary

Kita menggunakan dictionary Python yang bernama USER_DATABASE sebagai database simulasi. Key-nya berupa username, sedangkan value-nya adalah nilai hash yang dibuat dari password dummy. Struktur ini dipilih karena program dapat mengecek apakah username sudah ada dan mengambil hash milik username tertentu dengan mudah.

Dictionary ini masih tersimpan dalam memori runtime Google Colab, bukan database permanen. Ketika runtime di-reset, isinya bisa hilang. Fokus sesi ini adalah memahami logika penyimpanan hash dan autentikasi; bukan membangun layanan akun sungguhan.

Jika sudah terdaftar, program menampilkan pesan gagal dan menghentikan proses registrasi. Jika belum, program memanggil fungsi hash dan menyimpan hasilnya sebagai value dictionary.

Mengapa verifikasi dapat dilakukan?

Saat login, program tidak meminta database mengembalikan password asli. Program menghitung hash dari password yang baru dimasukkan. Jika input itu persis sama dengan password saat registrasi, output hash juga sama. Dengan membandingkan kedua nilai hash, program dapat menentukan apakah login cocok.

Jika username tidak ada, proses harus berhenti dengan pesan yang sesuai. Jangan langsung mengakses USER_DATABASE[username] tanpa pemeriksaan, karena key yang tidak ada dapat menimbulkan KeyError.

Membaca tiga hasil yang mungkin

Fungsi login memiliki tiga kemungkinan: username tidak ditemukan; username ada tetapi password tidak cocok; atau username dan password cocok. Semua jalur harus menghasilkan pesan yang mudah dimengerti. Pada kode sederhana ini, kecocokan hash diperiksa menggunakan ==.

Dalam aplikasi autentikasi nyata, perbandingan digest serta keseluruhan proses login perlu menggunakan pendekatan yang tahan serangan, termasuk pembandingan waktu-konstan bila relevan. Untuk latihan ini, fokusnya adalah urutan pemeriksaan dan tidak menyimpan plaintext.

Penyebab dan perbaikan

Salah satu error yang paling sering terjadi adalah memasukkan string ke hashlib.sha256(). Pesan TypeError menyatakan bahwa data harus diubah menjadi bytes terlebih dahulu. Tambahkan .encode("utf-8") pada string yang akan di-hash.

Jika TypeError muncul, periksa tipe data input. Dalam Python, type(password) bisa menunjukkan str, sedangkan type(password.encode("utf-8")) menghasilkan bytes. Mengubah tipe data sebelum hashing adalah bagian dari alur yang wajib ada.

Hash object tidak sama dengan hexdigest

Pemanggilan hashlib.sha256(data) menghasilkan objek yang merepresentasikan perhitungan hash. Ketika objek itu langsung dicetak, yang tampil bukan string hex yang ingin kamu simpan. Untuk mengambil hasil yang dapat dibaca dalam bentuk heksadesimal, panggil objek.hexdigest().

Sesudah perbaikan, nilai dapat dimasukkan ke dictionary dan dibandingkan dengan hasil hashing lain. Ingat, .hexdigest() adalah pemformatan digest sebagai teks, bukan proses membuka password atau melakukan dekripsi.

Boundary testing bukan sekadar berhasil sekali

Sistem autentikasi tidak boleh hanya diuji memakai satu login benar. Siswa perlu mencoba password salah dan username yang tidak terdaftar. Ulangi hashing input yang sama untuk mengecek sifat deterministik, lalu ubah satu huruf untuk melihat perbedaan digest. Lihat juga isi dictionary agar yakin hanya hash yang tersimpan.

Catat skenario mana yang lolos dan mana yang gagal. Jika login salah justru diterima, periksa operator pembanding. Jika username baru menimpa data lama, periksa kondisi duplikat. Jika hash tidak berukuran 64 karakter hex, periksa fungsi hash.

Batas keamanan yang wajib diketahui

SHA-256 cocok untuk banyak kebutuhan integritas data, tetapi jika digunakan langsung untuk menyimpan password tanpa salt, hasilnya dapat lebih mudah dicocokkan terhadap daftar tebakan atau tabel hash yang sudah dihitung. Sistem sungguhan memakai algoritma yang memang dirancang untuk hashing password, misalnya Argon2id, scrypt, atau bcrypt dengan parameter yang tepat.

Salt merupakan nilai acak unik untuk setiap akun yang membantu mencegah password identik menghasilkan representasi simpan yang identik. Salt bukan pengganti password kuat atau pembatasan percobaan login. Kita hanya mengenalkan konsepnya sebagai perluasan dari tugas kelas.
