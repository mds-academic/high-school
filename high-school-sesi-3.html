Kenapa Materi Sesi 2 Masih Penting?

Operator matematika hanya bisa bekerja dengan baik jika datanya sudah berbentuk angka. Karena hasil input() selalu string, harga yang dimasukkan pengguna perlu dikonversi dengan int() atau float().

Contoh

harga = int(input("Harga: ")) berarti program menerima input lalu langsung mengubahnya menjadi integer agar bisa dikalikan dan dijumlahkan.

Di sesi ini, kamu akan melihat hubungan yang lebih jelas antara tipe data dan operasi. Data yang salah tipe bisa membuat program error atau menghasilkan perilaku yang tidak diinginkan.

Konteks Perhitungan

Dalam simulasi ini, harga awal adalah Rp20.000. Pajak simulasi 11% berarti program perlu mencari 11 persen dari harga awal, bukan sekadar menambahkan angka 11.

Perhitungan manual

11% = 11/100 = 0.11. Jadi nilai pajak = 20.000 × 0.11 = 2.200. Total bayar = 20.000 + 2.200 = 22.200.

Komputer melakukan langkah yang sama. Bedanya, kita menuliskan aturan itu dalam bentuk variabel dan operator Python agar bisa dipakai untuk harga yang berbeda-beda.

Urutan Perhitungan Harus Jelas

Developer sebaiknya tidak langsung menulis banyak baris kode. Masalah dipecah dulu menjadi langkah yang saling bergantung.

Urutan project

  1. Ambil harga_awal.
  2. Tentukan tarif_pajak.
  3. Hitung nilai_pajak.
  4. Hitung total_bayar.
  5. Tampilkan nota.

Perhatikan bahwa total_bayar belum bisa dihitung sebelum nilai_pajak diketahui. Inilah alasan urutan proses penting.

Dekomposisi Menjadi Variabel

Daripada menulis satu rumus panjang, perhitungan dibagi menjadi beberapa variabel. Cara ini membuat kode lebih mudah dibaca dan lebih mudah diuji.

Contoh hubungan

nilai_pajak bergantung pada harga_awal dan tarif_pajak. Setelah itu, total_bayar bergantung pada harga_awal dan nilai_pajak.

Jika hasil total salah, kamu bisa mencetak nilai pajak terlebih dahulu untuk mengetahui apakah kesalahannya terjadi pada langkah pertama atau kedua.

Bridging dari Input ke Perhitungan

Pada sesi sebelumnya, kamu belajar bahwa input() selalu menghasilkan string. Agar harga bisa dikalikan dengan 0.11, nilainya perlu diubah menjadi tipe numerik.

Dua pilihan

int() cocok untuk harga dalam angka bulat. float() cocok jika program perlu menerima angka desimal.

Untuk jalur utama project ini, kita bisa memakai int(input(...)). Modul juga memperkenalkan float(input(...)) sebagai perluasan ketika input desimal dibutuhkan.

Tiga Operator Inti

Project ini cukup memakai tiga operator utama. Operator pembagian dipakai untuk mengubah persentase menjadi desimal, perkalian untuk mencari nilai pajak, dan penjumlahan untuk mendapatkan total akhir.

Jangan tertukar

Kesalahan operator bisa menghasilkan logic error. Program tetap berjalan tanpa pesan merah, tetapi hasilnya salah.

Karena logic error tidak selalu terlihat sebagai error teknis, kamu perlu membandingkan hasil program dengan perhitungan manual atau test case.

Mengubah Persen Menjadi Desimal

Komputer tidak membaca simbol persen seperti kita membaca tulisan sehari-hari. Untuk menghitung 11% dari suatu nilai, kita mengubahnya menjadi 11 / 100 atau langsung memakai 0.11.

Contoh

100000 * 0.11 menghasilkan 11000. Nilai itulah yang menjadi pajak simulasi.

Jika nanti persentase disimpan sebagai angka 11, rumusnya bisa ditulis persen / 100 sebelum dikalikan dengan harga.

Melihat Urutan Operasi di Kode

Di editor ini, setiap langkah dibuat sebagai variabel terpisah. Ini memudahkan kamu melihat perubahan nilai dari satu tahap ke tahap berikutnya.

Prediksi sebelum Run

Untuk harga 100000, tarif_pajak menjadi 0.11, nilai_pajak menjadi 11000.0, dan total_bayar menjadi 111000.0.

Perkalian dengan angka desimal membuat hasil menjadi float. Hal ini normal. Nanti kita akan membahas cara membuat tampilan nominal lebih rapi.

Pembulatan untuk Hasil Perhitungan

round() membulatkan nilai ke bilangan terdekat, sedangkan int() hanya mengambil bagian bilangan bulat dan membuang bagian desimal.

Contoh

round(2200.66) menjadi 2201, sedangkan int(2200.66) menjadi 2200.

Untuk project ini, lesson plan menekankan penggunaan round() pada hasil perhitungan agar logika pembulatan lebih sesuai daripada sekadar memotong angka.

Kenapa Menghitung Manual?

Komputer bisa menjalankan rumus dengan cepat, tetapi kamu tetap perlu tahu apakah hasilnya masuk akal. Perhitungan manual menjadi acuan saat melakukan testing.

Jawaban

11% dari 200000 adalah 22000. Total akhirnya adalah 222000.

Jika program menampilkan angka yang jauh berbeda, berarti ada kemungkinan operator atau urutan perhitungannya salah. Inilah cara sederhana mendeteksi logic error.

Membaca Kode Sebelum Menjalankan

harga_buku adalah integer, tetapi tarif_pajak adalah float karena nilainya 0.11. Ketika operasi melibatkan float, hasilnya juga menjadi float.

Prediksi

50000 * 0.11 menghasilkan 5500.0. Fungsi type() akan menunjukkan <class 'float'>.

Kebiasaan memprediksi output membantu kamu memahami alur program tanpa selalu bergantung pada tombol Run.

Checkpoint 1: Input Berjalan

Project dibangun sedikit demi sedikit. Checkpoint pertama hanya memastikan program bisa menerima harga awal dan menampilkannya kembali.

Format input

Ketik angka murni seperti 100000. Jangan mengetik Rp100.000 karena int() tidak dapat mengubah teks tersebut menjadi integer.

Jika bagian ini sudah berhasil, baru lanjut ke perhitungan pajak.

Checkpoint 2: Proses Pajak

Setelah input aman, tambahkan tarif_pajak = 0.11 dan hitung nilai_pajak. Fungsi round() digunakan agar hasil akhirnya menjadi bilangan bulat yang lebih mudah ditampilkan.

Checkpoint 3: Total Akhir

Setelah nilai pajak tersedia, total bayar cukup dihitung dengan penjumlahan harga_awal + nilai_pajak.

Jika program berjalan tetapi totalnya salah, itu bukan selalu SyntaxError. Bisa saja rumusnya memakai operator yang salah. Ini disebut logic error.

int() dan float() Sesuai Kebutuhan
