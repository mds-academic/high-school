tambah_pengeluaran()

Function ini mengubah input user menjadi Dictionary, lalu menyimpannya ke dalam List state.

def tambah_pengeluaran():
    print("
--- FITUR: TAMBAH PENGELUARAN ---")
    nama = input("Masukkan nama pengeluaran: ").strip()

    try:
        nominal = float(input("Masukkan nominal (Rp): "))
        transaksi = {
            "nama": nama,
            "nominal": nominal
        }
        riwayat_pengeluaran.append(transaksi)
        print(f"✅ Berhasil mencatat: {nama} sebesar Rp {nominal:,.0f}")
    except ValueError:
        print("🚨 Gagal: Nominal harus berupa angka!")

lihat_riwayat()

Function ini membaca semua data yang tersimpan di state.

def lihat_riwayat():
    print("
--- FITUR: RIWAYAT PENGELUARAN ---")

    if not riwayat_pengeluaran:
        print("⚠️ Belum ada catatan pengeluaran.")
    else:
        total = 0
        print("No. | Nama Pengeluaran       | Nominal")
        print("-----------------------------------------")
        for idx, item in enumerate(riwayat_pengeluaran, 1):
            print(f"{idx}.  | {item['nama']:<22} | Rp {item['nominal']:,.0f}")
            total += item['nominal']
        print("-----------------------------------------")
        print(f"Total Pengeluaran : Rp {total:,.0f}")

hapus_transaksi_terakhir()

.pop() menghapus item paling akhir dari List.

def hapus_transaksi_terakhir():
    print("
--- FITUR: HAPUS TRANSAKSI TERAKHIR ---")

    if not riwayat_pengeluaran:
        print("⚠️ Tidak ada data yang dapat dihapus.")
    else:
        dihapus = riwayat_pengeluaran.pop()
        print(f"🗑️ Berhasil menghapus transaksi: {dihapus['nama']} (Rp {dihapus['nominal']:,.0f})")

Kenapa dicek dulu?

Kalau .pop() dipanggil saat List kosong, Python bisa memunculkan IndexError.

Bug: Data Selalu Kosong

Gejala

User sudah menambah data, tapi saat lihat riwayat tetap kosong.

Kemungkinan penyebab

riwayat_pengeluaran = [] diletakkan di dalam loop atau function.

Perbaikan

Pindahkan inisialisasi List ke cell awal, di luar loop dan function.

Bug: NameError

NameError: name 'riwayat' is not defined

Artinya

Python tidak menemukan variabel yang kamu panggil di scope saat ini.

Quick check

Kalau variabel dibuat di dalam function A, apakah function B otomatis bisa membacanya?

Bug: KeyError

KeyError: 'Nama'

Salah

Menyimpan key "nama", tapi membaca "Nama".

Benar

Gunakan key yang sama persis. Dictionary bersifat case-sensitive.

Bug: pop from empty list

IndexError: pop from empty list

Solusi

Selalu cek kondisi List sebelum .pop().

if not riwayat_pengeluaran:
    print("⚠️ Tidak ada data yang dapat dihapus.")
else:
    dihapus = riwayat_pengeluaran.pop()

def hapus_semua_data():

Kenapa sesi ini penting?

Di sesi sebelumnya, function sudah membuat project lebih rapi. Namun, function yang hanya menerima input dan mencetak output belum tentu membuat aplikasi “mengingat” data. Begitu function selesai, data lokal bisa hilang.

Sesi 19 menambahkan konsep state management. Dengan List dan Dictionary, program dapat menyimpan daftar transaksi sementara selama aplikasi berjalan di Google Colab.

Inti materi

Data harus diletakkan di tempat yang tepat: di luar function dan di luar loop utama jika ingin dipakai oleh banyak fitur.

Yang akan kamu kuasai

Setelah sesi ini, kamu tidak hanya membuat function yang berjalan sendiri-sendiri. Kamu mulai menghubungkan function dengan memori aplikasi.

Skill pentingnya adalah memilih struktur data sesuai kebutuhan. Riwayat transaksi cocok memakai List. Satu transaksi yang punya beberapa field, seperti nama dan nominal, cocok memakai Dictionary. Jika transaksinya banyak, kita gabungkan menjadi List of Dictionary.

Dari modular ke terintegrasi

Function adalah langkah pertama untuk merapikan project. Namun, aplikasi yang terasa utuh butuh data yang bisa dibaca lintas fitur.

Contoh: fitur tambah pengeluaran harus memperbarui data. Fitur lihat riwayat harus membaca data yang sama. Fitur hapus transaksi harus mengubah data yang sama. Itulah alasan state diletakkan di luar function.

State dalam bahasa sederhana

Bayangkan state seperti catatan sementara di meja kerja program. Saat user menambah transaksi, catatan itu bertambah. Saat user melihat riwayat, program membaca catatan yang sama. Saat user menghapus transaksi terakhir, catatan itu berubah.

Selama runtime masih berjalan dan cell inisialisasi tidak di-reset, state bisa tetap dipakai. Namun, state ini belum permanen seperti database atau file.

Data sementara, bukan permanen

Di Google Colab, variabel disimpan di memori runtime. Selama runtime masih aktif, data bisa bertahan. Tetapi kalau runtime disconnect, notebook di-restart, atau cell inisialisasi dijalankan ulang dari awal, List bisa kembali kosong.

Ini bukan kekurangan, tapi batasan latihan. Untuk sesi ini, targetnya memahami penyimpanan sementara sebelum nanti belajar penyimpanan yang lebih permanen.

Kenapa List of Dictionary?

Jika hanya menyimpan nama pengeluaran, List biasa sudah cukup. Namun project finansial biasanya butuh lebih dari satu informasi: nama, nominal, mungkin kategori, tanggal, atau catatan. Karena itu, satu transaksi lebih rapi disimpan sebagai Dictionary.

Karena transaksinya bisa banyak, Dictionary tersebut dikumpulkan di dalam List. Inilah pola List of Dictionary.

Kenapa harus dummy?

Project ini hanya simulasi. Tujuannya belajar logika data, bukan mengumpulkan informasi pribadi. Karena itu, gunakan angka latihan dan nama fiktif.

Saat meminta bantuan debugging, cukup kirim kode, error message, dan input contoh. Jangan mengirim saldo asli, nomor rekening, kata sandi, PIN, NIK, atau data pribadi lain.

Kesalahan yang sering terjadi

Jika riwayat_pengeluaran = [] ditaruh di dalam while True, setiap kali menu diulang, List dibuat kosong lagi. Akibatnya data yang baru ditambahkan seperti tidak pernah tersimpan.

Untuk state yang ingin dipakai bersama, buat List di bagian inisialisasi, sebelum function dan sebelum main menu loop berjalan.

Kenapa bisa NameError?

Variabel yang dibuat di dalam function bersifat lokal. Artinya, variabel itu hanya hidup di dalam function tersebut. Function lain tidak otomatis bisa membacanya.

Solusi untuk project ini adalah membuat riwayat_pengeluaran di luar function. Dengan begitu, function tambah, lihat, dan hapus bisa menggunakan List yang sama.

Menu sebagai pengarah

Main menu tidak perlu menyimpan semua detail kode. Tugasnya adalah membaca pilihan user dan memanggil function yang tepat.

Function-lah yang berinteraksi dengan state: menambah data, membaca data, menghitung total, atau menghapus data terakhir.

Peran cell inisialisasi

Cell ini seperti menyiapkan meja kerja sebelum aplikasi berjalan. List riwayat_pengeluaran dimulai dari kosong, lalu bertambah saat user memilih fitur tambah pengeluaran.

profil_aplikasi dipakai sebagai contoh Dictionary untuk data berlabel tunggal, seperti nama pengguna simulasi dan mata uang.

Membaca function tambah

Urutannya: minta nama, minta nominal, buat Dictionary transaksi, lalu tambahkan ke List dengan .append(). Setelah itu, data menjadi bagian dari state dan bisa dibaca oleh fitur lain.

Di sesi 19, error handling masih sederhana. Nanti di sesi 20, bagian input nominal akan dibuat lebih kuat dengan validation loop.

Key membuat data mudah dibaca

Dictionary membantu kita menyimpan data yang punya label. Tanpa label, kamu harus mengingat urutan data. Dengan Dictionary, kode menjadi lebih jelas karena kita bisa membaca key-nya.

Ini penting untuk project yang nanti berkembang. Kalau suatu saat transaksi punya kategori atau tanggal, kamu cukup menambahkan key baru.

Bagian yang perlu diperhatikan

if not riwayat_pengeluaran mengecek apakah List masih kosong. Ini mencegah tampilan riwayat kosong yang membingungkan.

enumerate(..., 1) memberi nomor urut mulai dari 1. Di dalam loop, program membaca setiap Dictionary lalu mengambil nama dan nominal.

Hapus dengan pengamanan

.pop() berguna untuk menghapus data terakhir. Namun, sebelum memanggilnya, cek dulu apakah List tidak kosong. Ini adalah bentuk defensive coding sederhana.

Jika ada data, item terakhir dihapus dan dikembalikan ke variabel dihapus. Karena item itu Dictionary, kita masih bisa membaca dihapus['nama'] dan dihapus['nominal'] untuk pesan konfirmasi.

Yang berubah dari sesi sebelumnya

Main menu sekarang bukan hanya memanggil function yang berdiri sendiri. Setiap function terhubung ke state yang sama.

Ketika user memilih 1, List bertambah. Ketika user memilih 2, List yang sama dibaca. Ketika user memilih 3, item terakhir dari List yang sama dihapus. Inilah inti Data Integration.

Gunakan simulator ini untuk tracing

Simulator membantu kamu melihat bahwa state berubah langkah demi langkah. Saat tombol tambah diklik, data masuk ke List. Saat pop diklik, data terakhir keluar. Saat reset diklik, kondisi seperti runtime baru dimulai: List kembali kosong.

Di Google Colab, perubahan ini terjadi saat function dipanggil dari main menu. Prinsipnya sama seperti simulator.

Kenapa testing harus berurutan?

Untuk menguji state, urutan tindakan sangat penting. Kamu perlu melihat apakah data tetap ada setelah berpindah menu, bukan hanya memastikan satu function berjalan.

Test yang baik mengecek kondisi awal, tambah data, lihat data, hapus data, lihat sisa data, dan kondisi saat data kosong.

Cara mengecek

Cari baris riwayat_pengeluaran = []. Kalau baris itu berada di dalam while True atau di dalam function tambah/lihat, pindahkan ke bagian atas.

Baris inisialisasi hanya boleh dijalankan untuk memulai state baru. Jangan biarkan ia terpanggil setiap kali menu berputar.

Scope itu batas wilayah

Variabel lokal tidak bisa sembarang dipanggil dari tempat lain. Untuk state yang dipakai banyak function, buat variabelnya di luar function.

Alternatif lain adalah mengembalikan data dengan return, tetapi untuk project sesi 19 pola yang digunakan adalah shared state berupa List di level atas.

Key harus konsisten

Dictionary membedakan huruf besar dan kecil. 'nama' berbeda dengan 'Nama'. Jika kamu salah menulis key, Python tidak menemukan data yang diminta.

Untuk menghindari error ini, tentukan standar key sejak awal dan gunakan terus dengan ejaan yang sama.

Kenapa bisa terjadi?

.pop() butuh item untuk dihapus. Kalau List kosong, tidak ada item yang bisa diambil sehingga muncul IndexError.

Pengecekan if not riwayat_pengeluaran membuat program memberi pesan yang ramah alih-alih crash.

Kenapa perlu konfirmasi?

.clear() menghapus seluruh isi List. Karena efeknya besar, program sebaiknya meminta konfirmasi user terlebih dahulu.

Ini juga latihan membuat fitur yang lebih aman. Tidak semua aksi sebaiknya langsung dijalankan tanpa tanya ulang, apalagi aksi yang menghapus data.

Ringkasan pola

Kalau kamu bingung saat membuat project mandiri, kembali ke pola ini. Mulai dari state, buat function, hubungkan ke menu, lalu test alurnya.

Pola ini bisa dipakai untuk Budget Tracker, Smart Cashier, Portfolio Manager, atau project finansial lain yang butuh menyimpan data sementara.

Log juga membantu guru melihat proses berpikir kamu: struktur data, alasan, hasil testing, dan rencana perbaikan berikutnya.

Refleksi ini juga menjadi jembatan ke sesi 20, saat state yang sudah dibuat akan diamankan dari input yang salah.

Rangkuman akhir

State management membuat aplikasi CLI terasa lebih nyata. Data bisa bertambah, dibaca kembali, dihitung, dan dihapus selama program berjalan.

Di sesi berikutnya, kamu akan mengamankan titik input penting. Dengan begitu, aplikasi tidak hanya bisa mengingat data, tetapi juga tahan terhadap kesalahan input pengguna.
