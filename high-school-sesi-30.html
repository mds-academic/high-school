Data yang berhasil diperoleh harus disertai informasi waktu pembaruan, serta ditangani dengan aman jika jaringan atau data tidak tersedia. Bedakan data tetap dan data server

Saat belajar operasi matematika, kita sering memakai kurs simulasi seperti Rp15.000 per USD. Angka tersebut memudahkan pengujian rumus, tetapi tidak otomatis mengikuti pasar. Untuk mengambil data yang disediakan pihak lain, aplikasi bisa memanggil API.

Tetapi memperoleh data lewat internet tidak berarti nilai itu selalu paling baru, selalu benar, atau selalu cocok untuk transaksi bank. Periksa sumber, waktu update, dan batasan penggunaannya. Dalam kalkulator kita, data dari API berfungsi sebagai referensi pembelajaran, sementara pengujian matematika dapat memakai angka simulasi yang sudah diketahui.

Komunikasi dua arah melalui HTTP

Client adalah program yang meminta data, sedangkan server adalah sistem yang menyediakan respons. Program Google Colab bertindak sebagai client ketika menjalankan requests.get(). Endpoint API merupakan alamat yang dituju. Server kemudian mengirim respons HTTP, termasuk status dan konten data jika tersedia.

Jangan samakan request dan response. Request dikirim dari program ke server; response diterima program dari server. Dalam proyek ini, response yang berhasil biasanya berisi informasi kurs mata uang dalam format JSON.

Mengapa endpoint berakhir dengan USD?

Endpoint proyek meminta satu kumpulan kurs dengan USD sebagai mata uang dasar. Artinya respons diharapkan berisi nilai berbagai mata uang untuk satu unit USD. Karena target proyek adalah USD ke IDR, kita mencari kunci IDR di dalam objek rates.

Alamat endpoint adalah milik layanan eksternal, sehingga akses, struktur data, maupun ketersediaannya dapat berubah. Jika program tidak memperoleh data, periksa koneksi dan respons server; jangan langsung menganggap algoritma perhitungan salah.

Apa fungsi requests dan timeout?

requests adalah pustaka Python eksternal yang mempermudah komunikasi HTTP. Method requests.get(url) mengirim permintaan mengambil data ke URL yang ditentukan. Parameter timeout=6 membatasi waktu tunggu agar program tidak menunggu terlalu lama ketika koneksi lambat atau server tidak merespons.

Potongan kode ini hanya menunjukkan sintaks dasar. Di project sesungguhnya, panggilan jaringan dibungkus try-except dan status respons diperiksa sebelum JSON dipakai. Ingat, timeout bukan jaminan setiap request selesai dalam enam detik total; ia merupakan batas waktu yang diterapkan oleh library pada operasi jaringan tertentu.

Mengapa perlu melihat status code?

Respons HTTP memiliki status yang memberi informasi apakah request berhasil ditangani. Status 200 menunjukkan sukses secara HTTP, tetapi program tetap perlu mengecek apakah data JSON mengandung informasi yang diperlukan. Status 404 berarti sumber tidak ditemukan, sedangkan 429 menandakan terlalu banyak permintaan. Kode 500 biasanya menunjukkan masalah pada sisi server.

Dalam aplikasi yang baik, status gagal tidak boleh dianggap sama dengan kurs nol. Jika request gagal, tampilkan pesan yang jelas dan jangan menjalankan kalkulasi dengan data yang tidak valid.

Mengantisipasi hasil request

Gunakan simulasi untuk memutuskan langkah selanjutnya pada setiap status. Jika 200, program boleh melanjutkan parsing, tetapi tetap memvalidasi struktur JSON. Jika 404, URL mungkin salah atau sumber sudah berpindah. Jika 429, client perlu mematuhi batas permintaan server dan tidak mengirim ulang request secara agresif. Jika offline, tampilkan pesan koneksi gagal.

Perhatikan bahwa status HTTP hanya muncul jika server sempat memberi respons. Jika tidak ada koneksi atau terjadi timeout, Python mungkin melempar exception sebelum memperoleh status code. Karena itu, kita memerlukan dua jenis pemeriksaan: status respons dan penanganan exception.

Menghubungkan JSON dengan dictionary

JSON adalah format teks yang lazim digunakan untuk pertukaran data. Ketika diurai dengan response.json(), objek JSON biasanya berubah menjadi dictionary Python, sedangkan array menjadi list. Contoh di slide menunjukkan dictionary yang memiliki key base_code, rates, dan time_last_update_utc.

Di dalam rates ada dictionary lain. Karena itu kita dapat membaca data["rates"]["IDR"]. Pahami dulu struktur key yang bersarang, karena kesalahan akses key dapat menimbulkan KeyError ketika format respons tidak seperti yang diharapkan.

Alur parsing yang benar

Setelah memperoleh status sukses, program menggunakan response.json() untuk mengurai teks JSON menjadi struktur Python. Dengan data_json.get("rates", {}), program mengambil dictionary rates atau dictionary kosong jika key tersebut tidak ada. Berikutnya rates.get("IDR", 0) mengambil kurs IDR atau nilai default nol.

Nilai default tidak boleh langsung dipakai untuk perhitungan jika sebenarnya berarti “data tidak tersedia”. Pastikan kurs benar-benar ada, numerik, dan positif sebelum memakainya. Karena respons berasal dari layanan eksternal, validasi struktur merupakan bagian penting dari pemrograman defensif.

Kenapa program perlu jalur gagal?

Koneksi internet dapat putus, DNS bermasalah, atau server tidak merespons. Masalah-masalah ini biasanya tidak disebabkan oleh rumus konversi. Jika tidak ditangani, exception dapat menghentikan eksekusi program dan menampilkan traceback yang panjang.

Blok try-except memungkinkan program memberikan pesan yang lebih mudah dipahami. Namun, jangan menyembunyikan semua jenis error tanpa alasan. Tangkap requests.exceptions.RequestException untuk kategori kesalahan request. Jika parsing JSON atau format data tidak sesuai, penanganannya perlu dibedakan dengan jelas.

Fungsi yang mudah diuji

Di Student Project, fungsi ambil_kurs_terbaru() bertanggung jawab mengambil data dari API. Fungsi ini tidak perlu langsung mengerjakan perhitungan USD. Memisahkan pengambilan data dan kalkulator membuat setiap bagian lebih mudah ditest serta diperbaiki.

Teacher Project mengembalikan tiga informasi: status berhasil/gagal, data rates atau pesan error, dan waktu update. Sesuaikan struktur return sesuai kerangka notebook Student. Cek terlebih dulu apakah request berhasil, baru kemudian membaca data.

Menghindari KeyError saat membaca respons

Akses dictionary menggunakan tanda siku, seperti data["rates"], dapat memunculkan KeyError jika key tidak tersedia. Method .get() memberikan nilai default ketika key tidak ditemukan. Dalam proyek, dictionary kosong dipakai sebagai default ketika rates tidak ada.

Tetapi jangan menyimpulkan bahwa kode sudah benar hanya karena tidak mengalami KeyError. Jika rates kosong, tidak ada angka kurs yang bisa dikonversi. Tambahkan validasi agar program memberi pesan yang menjelaskan data belum tersedia dan tidak menghasilkan angka Rupiah palsu.

Mengapa operasi perkalian?

Endpoint yang kita gunakan memberikan kurs dengan dasar satu USD. Jika satu USD bernilai Rp15.000 dalam simulasi, maka sepuluh USD bernilai sepuluh kali angka itu, yaitu Rp150.000. Karena itu rumus yang digunakan adalah nominal_usd * kurs_idr.

Format :,.2f pada f-string menampilkan pemisah ribuan dan dua angka desimal dengan gaya default Python (koma sebagai pemisah ribuan dan titik sebagai desimal). Ini bukan otomatis format lokal Indonesia. Jika ingin tampilan angka bergaya Indonesia, perlu penyesuaian format tambahan.

Mengapa pengujian offline berguna?

Kita perlu memastikan bahwa rumus konversi bekerja terlepas dari kondisi jaringan. Simulator ini memakai angka contoh yang diketahui sehingga hasilnya dapat dihitung manual. Coba USD 50 dan kurs Rp15.650, lalu verifikasi hasilnya Rp782.500. Kamu juga bisa mengganti angka untuk mengecek apakah perubahan nominal berdampak pada hasil secara benar.

Ini berbeda dari proyek utama yang mengambil kurs dari API. Dalam Student Project, kalkulator menggunakan kurs yang berhasil diterima dari server. Saat server gagal, program harus memberitahu pengguna bahwa data tidak tersedia alih-alih diam-diam menganggap simulasi sebagai kurs live.

Bagaimana jika pengguna mengetik huruf?

Fungsi float() mengubah string numerik menjadi bilangan desimal. Jika pengguna mengetik teks seperti abc, Python akan menghasilkan ValueError. Dengan try-except ValueError, program dapat menampilkan instruksi koreksi. Kamu juga dapat memeriksa bahwa nominal tidak negatif sebelum menghitung total.

Perhatikan bahwa penanganan kesalahan input dan penanganan kesalahan jaringan adalah dua hal berbeda. Keduanya diperlukan agar kalkulator dapat memberi hasil yang masuk akal dan pesan yang jelas ketika proses gagal.

Mengapa kode pendek belum tentu aman?

Potongan tiga baris yang langsung meminta data dan membaca rates["IDR"] mungkin berhasil ketika server baik-baik saja. Namun, ia mengabaikan jaringan lambat, status error, JSON yang tidak sesuai, atau key yang tidak ada. Program seolah menganggap kondisi ideal selalu terjadi.

Dalam debugging, identifikasi di mana suatu asumsi dibuat. Setelah request, cek apakah respons tersedia dan status sukses. Setelah parsing, cek apakah struktur data benar. Sebelum kalkulasi, cek bahwa kurs valid. Rangkaian ini merupakan inti pemrograman defensif ketika aplikasi menggunakan API pihak ketiga.

Pengujian yang dapat dilakukan di kelas

Pertama, coba request saat internet aktif. Jika berhasil, lihat waktu pembaruan dan kurs IDR yang ditampilkan. Kedua, uji masukan numerik yang mudah dihitung, misalnya 100 USD. Ketiga, coba teks abc untuk memastikan input salah ditangani. Keempat, diskusikan atau simulasikan skenario jaringan terputus dan respons tidak lengkap.

Karena API adalah layanan eksternal, guru bisa menggunakan data respons contoh ketika internet tidak tersedia. Beri label tegas bahwa contoh tersebut tidak live. Fokusnya adalah logika parsing, perhitungan, dan cara program menangani kondisi yang tidak ideal.

Memakai data eksternal dengan tanggung jawab

API publik mempunyai batas akses dan ketentuan penggunaan. Mengirim permintaan terlalu sering dapat membebani layanan dan menghasilkan status 429. Untuk kelas, lakukan pemanggilan seperlunya; jika hanya ingin mengetes rumus, gunakan kurs simulasi tanpa meminta data berulang-ulang.

Jika API menyediakan waktu pembaruan, tampilkan atau catat informasi tersebut agar pengguna tahu kapan data terakhir tersedia. Jangan menyimpan token atau API key rahasia dalam notebook yang akan dibagikan. Ingat pula bahwa kurs referensi dari layanan publik mungkin tidak sama dengan kurs jual/beli atau biaya transaksi dari lembaga keuangan.
