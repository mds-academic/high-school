Komputer menjalankan instruksi secara ketat. Kalau format data tidak sesuai dengan operasi yang diminta, eksekusi bisa berhenti.

Anatomi try-except ValueError

Struktur dasar terdiri dari blok kode yang dicoba dan blok penyelamat untuk error tertentu.

try:
    angka = int(input("Masukkan angka bulat: "))
    print(f"Angka valid: {angka}")
except ValueError:
    print("Input harus berupa angka bulat.")

Dari Input Salah ke Crash

input() selalu menghasilkan string. Ketika kita menulis int(input(...)), Python mencoba mengubah string itu menjadi integer. String seperti "1200000" dapat dikonversi, tetapi "seribu" tidak memiliki format bilangan bulat yang bisa dipahami oleh int().

Saat konversi gagal, Python memunculkan ValueError. Jika tidak ada kode yang menangani exception tersebut, alur eksekusi berhenti dan biasanya Colab menampilkan traceback merah. Dalam konteks aplikasi, pengalaman seperti ini terasa seperti program “crash”.

Error handling tidak membuat semua input menjadi benar. Fungsinya adalah membuat program tahu cara merespons ketika sesuatu yang sudah diperkirakan terjadi.

Bedakan masalahnya

Kalau rumus pembagianmu salah, itu bukan masalah yang otomatis diselesaikan oleh try-except. Error handling bukan pengganti debugging logika.

Tiga Istilah yang Sering Tercampur

Bug adalah kesalahan pada rancangan kode atau logika yang dibuat developer. Contohnya salah menulis nama variabel, salah rumus, atau membuat kondisi yang tidak sesuai kebutuhan.

Exception adalah masalah yang muncul saat program sedang berjalan. Di sesi ini, contoh utamanya adalah ValueError ketika string dari user tidak dapat dikonversi menjadi integer.

Crash adalah kondisi ketika program berhenti secara tidak normal. Exception yang tidak ditangani dapat membuat eksekusi berhenti, sehingga dari sudut pandang user program tampak crash.

Hubungannya

Tidak semua bug langsung memicu exception, dan tidak semua exception harus berakhir menjadi crash. Dengan error handling yang tepat, exception yang sudah diperkirakan dapat ditangani dengan aman.

Dua Jalur untuk Input yang Sama

Bayangkan user mengetik seribu. Tanpa try-except, baris int() memicu ValueError dan program berhenti sebelum bisa menampilkan pesan yang membantu user.

Dengan try-except, Python tetap mencoba konversi di dalam try. Ketika ValueError terjadi, Python tidak melanjutkan sisa blok try. Alur langsung berpindah ke except ValueError. Di sana kita dapat menampilkan instruksi yang lebih jelas, misalnya “Masukkan angka bulat tanpa huruf.”

Setelah blok except selesai, kode di luar pasangan try-except dapat tetap berjalan. Itu sebabnya project kita bisa mencetak pesan “Sistem selesai” meskipun format input salah.

Tujuan UX

User tidak perlu membaca traceback Python untuk tahu apa yang harus diperbaiki. Pesan error sebaiknya menjelaskan tindakan berikutnya.

Membaca Struktur try-except

try: menandai blok kode yang akan dicoba Python. Di sesi ini, bagian paling rawan adalah proses input dan type casting. Karena itu, int(input(...)) harus berada di dalam cakupan try.

except ValueError: adalah jalur yang dijalankan jika selama eksekusi blok try muncul ValueError. Kata ValueError penting karena kita sedang menangani jenis error tertentu: kegagalan karena nilai/format data tidak cocok untuk operasi konversi.

Indentasi menentukan struktur. Isi try menjorok empat spasi. Isi except juga menjorok empat spasi, tetapi baris try: dan except ValueError: sendiri harus sejajar.

Kesalahan umum

Menaruh int() sebelum try berarti exception terjadi sebelum “jaring pengaman” aktif.

Urutan Evaluasi Python

Python selalu memulai dari blok try. Selama tidak ada error, semua baris di dalamnya dijalankan seperti biasa. Jika blok selesai tanpa ValueError, bagian except ValueError dilewati.

Jika ValueError terjadi di tengah blok try, Python berhenti menjalankan sisa baris di blok tersebut. Program langsung berpindah ke blok except ValueError. Jadi, baris setelah titik error di dalam try tidak dijalankan pada percobaan itu.

Setelah try atau except selesai, eksekusi berlanjut ke baris berikutnya di luar struktur tersebut. Ini penting untuk memahami kenapa pesan “Sistem selesai” masih bisa muncul setelah input salah.

Teknik trace

Saat debugging, tandai baris terakhir yang sempat dijalankan. Itu membantu menemukan titik tempat alur berpindah.

Menangkap Error Secara Spesifik

Menulis except ValueError: lebih baik daripada except: untuk project ini karena kita tahu error apa yang sedang diantisipasi: kegagalan konversi input menjadi angka.

except: tanpa jenis exception dapat menangkap terlalu banyak masalah. Misalnya, jika ada nama variabel yang salah atau bug lain, program bisa tetap masuk ke blok except dan menampilkan “format input salah”, padahal penyebab aslinya berbeda.

Pesan yang salah membuat debugging membingungkan. Dengan exception yang spesifik, program hanya menangani skenario yang memang dirancang untuk ditangani, sementara bug lain tetap terlihat dan bisa diperbaiki.

Kebiasaan yang bagus

Tanyakan: “Error apa yang realistis terjadi di baris ini?” Lalu tangkap jenis error tersebut, bukan semua error sekaligus.

Input dan Type Casting

Karena input() menghasilkan string, project harus melakukan type casting sebelum nilai dipakai untuk perhitungan. Untuk target tabungan yang ditentukan sebagai angka bulat, kita memakai int().

"1200000" berisi karakter digit dan dapat menjadi integer. "seribu" tidak dapat dikonversi. String "1200000.5" juga tidak valid untuk int() karena memiliki format desimal. Input kosong sama sekali tidak memiliki digit yang bisa diubah menjadi integer.

Kalau project membutuhkan desimal, float() dapat digunakan. Namun float() tetap bisa memicu ValueError jika input berupa teks seperti "seribu".

Tipe data mengikuti kebutuhan

Jangan memilih int() atau float() hanya supaya error hilang. Pilih tipe yang sesuai dengan desain data project.

Dua Lapisan Validasi

Format validation menjawab pertanyaan: “Apakah input ini bisa dibaca dalam tipe data yang dibutuhkan?” Untuk project inti, mekanismenya adalah try-except ValueError di sekitar konversi int().

Logic validation menjawab pertanyaan berikutnya: “Setelah data berhasil dibaca, apakah nilainya masuk akal?” Input -1200000 lolos format karena merupakan integer, tetapi secara logika tidak cocok sebagai target tabungan.

Kedua lapisan ini saling melengkapi. Error handling tidak otomatis mengetahui aturan bisnis atau konteks project. Hanya developer yang bisa menentukan aturan seperti “target tidak boleh negatif”.

Pola berpikir

1) Ubah input menjadi tipe yang benar. 2) Setelah berhasil, periksa aturan nilainya. 3) Baru lakukan perhitungan utama.

Error Handling Bukan Loop

Di Sesi 9, while dipakai karena program perlu mengulang input sampai kondisi tertentu. Di Sesi 10, try-except punya tugas lain: menangani exception yang terjadi saat satu bagian kode dijalankan.

Jika user memasukkan teks dan program masuk ke except, struktur itu sendiri tidak otomatis kembali ke input(). Setelah except selesai, Python melanjutkan ke kode setelah pasangan try-except.

Nanti, jika dibutuhkan, kedua konsep bisa digabung. Misalnya while True mengulang permintaan input, sedangkan try-except menjaga konversi di setiap iterasi. Namun pada sesi ini, kamu perlu memahami tanggung jawab masing-masing struktur terlebih dahulu.

Jangan tertukar

while mengatur pengulangan. try-except mengatur respons terhadap exception.

Kalkulator Target Tabungan Anti-Crash menerima target tabungan simulasi dari user. Jika input dapat diubah menjadi integer, program membagi target tersebut dengan 12 untuk menghasilkan estimasi alokasi per bulan.

Project ini sengaja sederhana pada bagian perhitungan supaya fokus utama tetap pada robust input. Yang dinilai bukan seberapa rumit rumusnya, tetapi apakah dua jalur program bekerja dengan benar: jalur input valid dan jalur ValueError.

Alur build yang aman adalah kecil dan bertahap. Pertama, pastikan input + konversi bekerja. Kedua, tambahkan pembagian. Ketiga, tambahkan output. Terakhir, uji format yang salah. Jangan menunggu seluruh notebook selesai sebelum testing.

Mengamati Crash Secara Terkendali

Perhatikan bahwa tabungan_per_bulan tidak pernah dihitung dan print("Program selesai") tidak sempat dijalankan. Ini menunjukkan bahwa exception yang tidak ditangani memutus alur eksekusi.

Tujuan latihan

Bukan sekadar membuat error, tetapi mengenali di baris mana program berhenti dan mengapa.

Menangkap ValueError

Sekarang baris rawan error berada di dalam try. Ketika input seribu membuat int() gagal, Python langsung berpindah ke except ValueError dan mencetak pesan yang sudah kita siapkan.

Baris print("Sistem selesai tanpa crash.") berada di luar kedua blok. Karena exception sudah ditangani, baris tersebut tetap dijalankan setelah except selesai.

Coba beberapa input. Dengan angka valid, blok except dilewati. Dengan teks atau input kosong, blok except aktif. Tujuannya adalah melihat bahwa struktur yang sama dapat menangani dua jalur tanpa menghentikan program secara tidak normal.

Pesan error yang baik

Sebutkan apa yang salah dan format apa yang diharapkan user, bukan hanya “Error!”.

Testing Multi-Input

Program yang robust perlu diuji dengan variasi input. Angka normal mengecek jalur utama. Teks, desimal, dan input kosong mengecek apakah except ValueError benar-benar aktif. Nol dan negatif menguji nilai batas dan logika.

Menggunakan Trace untuk Debugging

Trace adalah cara membaca program langkah demi langkah. Untuk input seribu, alurnya: input diterima sebagai string → int() mencoba konversi → muncul ValueError → program pindah ke except → pesan akhir di luar blok tetap dijalankan.

Untuk input 1200000, alurnya berbeda pada titik konversi: int() berhasil → perhitungan 12 bulan dijalankan → except dilewati → pesan akhir muncul.

Trace membuat debugging lebih terarah. Daripada menebak-nebak, kamu bisa mencari titik pertama ketika nilai atau jalur aktual berbeda dari yang kamu prediksi.

Pertanyaan trace

“Apa nilai variabel sekarang?”, “Baris berikutnya yang dijalankan apa?”, dan “Apakah Python tetap di try atau pindah ke except?”

Debug: Cakupan Blok try

Pada contoh salah, target_angka = int(input(...)) ditulis sebelum try:. Artinya, jika user memasukkan teks, ValueError terjadi sebelum program memasuki area yang dilindungi.

Blok except ValueError hanya dapat menangani ValueError yang terjadi ketika blok try sedang dieksekusi. Ia tidak bisa “mundur” dan menangkap error yang sudah terjadi sebelumnya.

Perbaikannya adalah memindahkan proses input dan konversi ke dalam try. Setelah itu, perhitungan yang bergantung pada hasil konversi juga bisa diletakkan di jalur yang sama.

Checklist cepat

Tandai semua baris yang berpotensi memicu ValueError. Pastikan baris tersebut benar-benar berada di dalam blok try.

Debug: Struktur dan Indentasi

Python memakai indentasi untuk menentukan hubungan antarblok. try: dan except ValueError: adalah pasangan pada level yang sama, sehingga keduanya harus sejajar secara vertikal.

Isi try menjorok ke kanan. Isi except juga menjorok ke kanan dari baris except. Jika except ikut menjorok ke dalam try, struktur menjadi tidak valid dan Python dapat menampilkan error sintaks/indentasi.

Gunakan empat spasi secara konsisten di Colab. Ketika memindahkan kode, cek kembali garis vertikal indentasi, bukan hanya membaca teksnya.

Visual sederhana

try: dan except ValueError: sejajar. Baris di bawah masing-masing masuk satu tingkat ke kanan.

Format Input Harus Jelas

Python tidak otomatis memahami titik sebagai pemisah ribuan pada string untuk int(). Karena itu, int("1.200.000") gagal. User perlu memasukkan 1200000 jika program belum dibuat untuk membersihkan format angka.

Begitu juga dengan string desimal "1200000.5". Untuk int(), format tersebut tidak cocok. Jika kebutuhan aplikasinya memang menerima desimal, gunakan float() dan sesuaikan aturan output.

Pesan input merupakan bagian dari desain program. Semakin jelas format yang diminta, semakin kecil kemungkinan user bingung saat memasukkan data.

Instruksi yang baik

“Masukkan angka bulat tanpa huruf atau pemisah desimal” lebih jelas daripada hanya “Masukkan nominal”.

Logic Validation dengan if

Input negatif menunjukkan batas kemampuan try-except. int("-1200000") berhasil karena string tersebut memang representasi integer. Jadi tidak ada ValueError yang perlu ditangkap.

Namun dari konteks Kalkulator Target Tabungan, nilai negatif tidak masuk akal. Setelah type casting berhasil, gunakan if target_angka < 0: untuk menangani aturan tersebut. Jika nilainya tidak negatif, baru lakukan pembagian 12 bulan.

Dengan pola ini, program punya tiga kemungkinan jalur: format salah → except; format benar tetapi nilai negatif → if; format dan logika benar → else dan perhitungan.

Dua alat, dua tugas

try-except menjaga proses teknis. if menerapkan aturan logika aplikasi.
