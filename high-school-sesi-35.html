Struktur Fungsi Guru

def mesin_pemaaf_typo(kata_input):
    kata_bersih = kata_input.lower().strip()
    hasil_match = process.extractOne(kata_bersih, KAMUS_BAKU)
    if not hasil_match:
        return kata_bersih, 0, False
    kata_baku, skor = hasil_match
    if skor >= AMBANG_BATAS_TYPO:
        return kata_baku, skor, True
    return kata_bersih, skor, False

Audit

Output fungsi guru berupa tuple, bukan dictionary. Validasi input kosong/non-string belum ditambahkan pada fungsi ini.

Exact Matching Tidak Toleran Typo

Operator == hanya memeriksa apakah kedua string identik karakter demi karakter. Ia cocok ketika kode memang menuntut nilai yang persis sama.

Dalam sistem bantuan, istilah yang mirip perlu dipertimbangkan tanpa langsung diganti. Karena itu kita akan mencari kandidat terbaik, menampilkan skornya, lalu menggunakan threshold sebagai kontrol.

Levenshtein: Tiga Jenis Perubahan

Jarak edit Levenshtein menghitung jumlah operasi minimum untuk mengubah satu string menjadi string lain: menambah, menghapus, atau mengganti karakter. Ini dasar penting untuk memahami toleransi salah ketik.

Namun nilai similarity dari thefuzz tidak selalu sekadar 100 dikurangi edit distance. Fungsi berbeda bisa memakai formula berbeda, sehingga skor perlu dilihat dari runtime.

Kandidat Terbaik Tidak Selalu Benar

Saat mencari satu pilihan terbaik dari sebuah kamus, program akan memilih kandidat dengan skor relatif paling tinggi. Tetapi kandidat itu bisa saja masih jauh dari input. Itulah fungsi threshold: kita menetapkan batas minimum sebelum memakai hasil sebagai koreksi.

Bahkan hasil yang lolos threshold tidak selalu benar secara makna. Pada aplikasi finansial, jangan gunakan koreksi kata untuk menjalankan transfer atau membuka akses akun tanpa konfirmasi manusia.

process.extractOne(): Satu Kandidat Terbaik

Jika daftar kandidat kosong, hasil perlu dijaga agar tidak langsung di-unpack. Teacher Project memakai kamus yang sudah terisi sehingga latihan utama bisa dilakukan secara stabil.

Menguji Syarat Ambang 75

Operator >= berarti lebih besar atau sama dengan. Skor 75 tepat harus diterima; skor 74 belum memenuhi. Jangan memakai > bila tujuan modul mencakup nilai 75 sebagai diterima.

Setelah skor diperiksa, Teacher Project akan memilih kandidat baku jika valid; bila tidak, ia mempertahankan kata input yang sudah dibersihkan. Ini membantu menghindari koreksi yang terlalu agresif.

Trace Tuple vs Dictionary

Perhatikan kontrak data dari setiap fungsi. Fungsi utama mengembalikan tuple berurutan; wrapper mengembalikan dictionary yang dibaca lewat nama key. Jika kamu mencoba meng-unpack dictionary sebagai tiga nilai, yang didapat bisa key, bukan nilai yang diharapkan.

Jaga kedua fungsi sebagai dua bagian terpisah. Ini membuat kode guru tetap dapat digunakan untuk testing dan pengembangan laporan bisa berjalan secara aman.

Bahaya False Positive

Fuzzy matching berbasis kemiripan karakter tidak memiliki pemahaman semantik seperti manusia. Kata yang mirip tetapi berbeda arti masih bisa mendapat skor tinggi, khususnya jika kamusnya terbatas.

Pada sistem finansial, saran koreksi tidak boleh otomatis memicu transaksi. Tampilkan usulan lalu beri pengguna kesempatan mengonfirmasi bila tindakan sensitif akan dilakukan.

Debugging: ModuleNotFoundError

Kesalahan ModuleNotFoundError berarti library tidak ditemukan pada environment aktif. Proyek thefuzz membutuhkan paket tersedia agar fungsi bisa dijalankan.

Ketika instalasi tidak berhasil karena jaringan, catat kendalanya secara jelas dan gunakan contoh guru untuk membahas alur. Jangan mengaku skor sudah berhasil diuji jika runtime belum bisa menjalankan library.

Debugging: None dan Input Kosong

Fungsi awal yang langsung menjalankan kata_input.lower().strip() tidak aman untuk data bukan string. Wrapper perlu mengecek tipe dan isi terlebih dahulu.

Pada pengujian, bedakan error yang ditangani dari keputusan tidak melakukan koreksi. Input invalid tidak sama dengan kata valid yang skornya berada di bawah threshold.
