One-Shot vs Main Menu

Tanpa loop, program hanya punya satu kesempatan memilih. Dengan loop, menu bisa muncul lagi setelah fitur selesai.

One-shot

User memilih sekali, program selesai.

input → proses → output → selesai

Main menu loop

User bisa memilih fitur berkali-kali sampai memilih keluar.

menu → pilih → fitur → kembali ke menu

Kerangka Main Menu

while True:
    print("1. Cek budget")
    print("2. Hitung target tabungan")
    print("0. Keluar")

    pilihan = input("Pilih menu: ")

    if pilihan == "1":
        print("Jalankan fitur cek budget")
    elif pilihan == "2":
        print("Jalankan fitur target tabungan")
    elif pilihan == "0":

Kenapa Main Menu Penting?

Di sesi sebelumnya, prototype kamu masih seperti jalan satu arah: user mengisi data, program menampilkan hasil, lalu selesai. Itu bagus untuk versi awal, tetapi aplikasi terasa kurang fleksibel kalau user ingin mencoba fitur lain.

Main menu membuat CLI terasa seperti aplikasi sungguhan. User bisa memilih fitur, menjalankan fitur itu, lalu kembali lagi ke menu utama. Pola ini akan sering kamu temui di aplikasi terminal, game teks, sistem kasir sederhana, dan project Python berbasis pilihan.

Fokus sesi

Bukan menambah fitur sebanyak mungkin. Fokusnya adalah membuat alur menu yang jelas, tidak mudah nyangkut, dan bisa dites.

Alur Sesi

Kita akan mulai dari ide sederhana: menu yang muncul sekali. Setelah itu, kita ubah menjadi menu yang terus muncul selama user belum memilih keluar.

Di tengah proses, kamu akan belajar bagian penting seperti while True, break, pilihan sebagai teks, dan cara menangani input menu yang tidak tersedia. Semua ini akan dipakai untuk mengembangkan prototype Financial Helper CLI dari sesi 16.

Patokan belajar

Menu yang baik bukan hanya bisa berjalan. Menu yang baik juga jelas, punya pilihan keluar, dan memberi pesan saat user salah mengetik pilihan.

Persiapan Project

Sebelum menambah main menu, baca lagi prototype dari sesi 16. Cari bagian yang sudah bisa dijadikan fitur: misalnya cek budget, hitung target tabungan, atau rekomendasi keputusan beli.

Di sesi ini, kamu tidak perlu memasukkan data asli. Gunakan data dummy agar aman dan mudah dites. Contoh data dummy: pemasukan 2.500.000, kebutuhan 1.500.000, keinginan 500.000, target tabungan 1.200.000.

Checkpoint awal

Kalau prototype lama belum sempurna, tidak apa-apa. Yang penting kamu tahu bagian mana yang mau dimasukkan ke pilihan menu.

Dari Prototype ke Aplikasi yang Lebih Interaktif

Prototype sesi 16 sudah punya pondasi: input, proses, output, dan keputusan sederhana. Sesi 17 menambahkan lapisan interaksi di atasnya.

Bayangkan prototype lama seperti satu fitur yang langsung jalan. Main menu membuat beberapa fitur bisa diletakkan dalam satu tempat. User tidak perlu membuka code cell berbeda untuk mencoba fitur lain.

Perubahan utama

Dari “program berjalan sekali” menjadi “program menunggu pilihan user sampai user memilih keluar”.

Kenapa One-Shot Terasa Terbatas?

Program one-shot cocok untuk latihan konsep dasar. Namun, ketika project mulai punya lebih dari satu fitur, user akan repot kalau harus menjalankan ulang code cell setiap ingin mencoba fitur lain.

Main menu loop membuat pengalaman user lebih rapi. User melihat daftar fitur, memilih angka, menjalankan fitur, lalu bisa lanjut memilih fitur lain. Ini membuat prototype kamu lebih mudah didemokan di pitch deck atau presentasi.

Catatan

Main menu loop tetap perlu batas. Karena itu, selalu sediakan pilihan keluar seperti 0. Keluar.

Loop Bukan Sekadar Mengulang

Loop dalam main menu punya tujuan yang jelas: menjaga program tetap terbuka sampai user selesai. Jadi, setiap putaran loop harus melakukan tiga hal: menampilkan menu, membaca pilihan, lalu menjalankan bagian yang sesuai.

Setelah fitur selesai, program kembali ke awal loop. Kalau user memilih keluar, program menjalankan break untuk menghentikan loop.

Kalimat sederhana

Selama user belum memilih keluar, tampilkan menu lagi.

Loop Tak Terbatas yang Terkontrol

while True sering dipakai untuk menu karena kita belum tahu berapa kali user akan memakai aplikasi. Bisa sekali, bisa lima kali, bisa lebih. Karena kondisinya selalu benar, loop akan terus berputar.

Supaya loop tidak menjadi jebakan, kita butuh break. Biasanya break diletakkan pada pilihan keluar, misalnya saat user mengetik 0.

Ingat

while True aman dipakai kalau kamu punya kondisi keluar yang jelas.

Kenapa Pilihan Menu Tidak Harus Diubah Jadi Angka?

Angka menu sebenarnya hanya label pilihan. Program tidak perlu menghitung pilihan + 1. Jadi, pilihan bisa tetap berupa teks.

Dengan pilihan sebagai teks, program lebih tahan saat user mengetik input yang tidak sesuai. Misalnya user mengetik x, program bisa masuk ke bagian else dan menampilkan pesan “Pilihan tidak tersedia” tanpa langsung crash.

Bedakan

Pilihan menu boleh teks. Tetapi data untuk perhitungan, seperti pemasukan atau target tabungan, tetap perlu diubah menjadi int atau float.

Bagian-Bagian Kerangka

Kerangka ini terdiri dari tiga bagian besar. Pertama, loop while True. Kedua, tampilan menu dan input pilihan. Ketiga, cabang if/elif/else untuk menentukan tindakan.

Bagian else penting karena user bisa saja mengetik pilihan yang tidak ada. Tanpa else, program terlihat diam atau membingungkan.

Jangan lupa indentasi

Semua isi loop harus menjorok ke dalam. Isi setiap if atau elif juga harus menjorok lagi.

Cabang Harus Eksklusif

Dalam menu, satu pilihan seharusnya menjalankan satu jalur. Kalau user memilih 1, program cukup menjalankan fitur 1. Ia tidak perlu mengecek semua fitur seolah-olah semuanya bisa terjadi bersamaan.

Karena itu, pola if/elif/else cocok untuk routing menu. Setelah satu kondisi benar, Python tidak melanjutkan ke cabang elif lain di level yang sama.

Analogi

Seperti memilih nomor antrean layanan. Satu nomor membawa user ke satu loket, bukan semua loket sekaligus.

Pesan Error yang Ramah

Untuk CLI, pesan seperti “Pilihan tidak tersedia” jauh lebih membantu daripada program berhenti tanpa penjelasan. User jadi tahu bahwa inputnya tidak cocok dengan daftar menu.

Di tahap ini, kita belum membuat validasi yang sangat kompleks. Cukup pastikan pilihan yang tidak ada masuk ke else, lalu loop kembali menampilkan menu.

Hindari

Jangan membuat user menebak-nebak. Beri tahu pilihan yang valid, misalnya “Ketik 1, 2, 3, 4, atau 0”.

Pseudocode Membuat Loop Lebih Aman

Main menu bisa membingungkan kalau langsung ditulis sebagai kode tanpa rancangan. Pseudocode membantu kamu melihat urutan fitur, pilihan keluar, dan respons untuk input salah.

Gunakan kata-kata seperti WHILE, IF, ELSE IF, dan STOP loop. Walaupun belum Python, struktur ini sudah dekat dengan kode yang akan kamu tulis.

Tips

Kalau pseudocode kamu tidak punya pilihan keluar, kode Python kamu kemungkinan juga akan sulit berhenti.

Membangun Pseudocode Bertahap

Kamu tidak perlu menulis pseudocode sempurna dalam satu kali percobaan. Mulai dari struktur besar: mulai, ulangi menu, baca pilihan, jalankan fitur, keluar, dan tangani input salah.

Setelah struktur besar jelas, baru isi detail fitur. Misalnya, untuk fitur cek budget: input pemasukan, input pengeluaran, hitung sisa, lalu tampilkan status.

Jangan terlalu detail dulu

Pseudocode bukan tempat menulis semua baris Python. Fokus pada alur dan keputusan penting.

State Sederhana dalam Program

last_summary adalah contoh state sederhana: data kecil yang disimpan program untuk dipakai lagi nanti. Selama loop masih berjalan, variabel ini bisa diperbarui oleh fitur lain.

Di project besar, state bisa berupa list, dictionary, atau file. Untuk sesi ini, satu variabel ringkasan sudah cukup untuk menunjukkan bahwa aplikasi CLI bisa mengingat hasil terakhir.

Jangan berlebihan

Sesi 17 fokus pada main menu loop. Penyimpanan data yang lebih rapi bisa dikembangkan di sesi lain sesuai arahan guru.

Menguji Ringkasan

Input simulator dimulai dari 4, jadi program menampilkan ringkasan saat belum ada fitur yang dijalankan. Setelah itu user memilih 1, memasukkan data budget, lalu memilih 4 lagi.

Kalau kode benar, ringkasan kedua seharusnya berubah. Ini membuktikan bahwa variabel last_summary berhasil diperbarui di dalam loop.

Ini test yang bagus

Karena tidak hanya mengetes fitur utama, tetapi juga mengetes urutan penggunaan aplikasi.

Break Bukan Dekorasi

Di menu loop, break adalah perintah yang benar-benar menghentikan loop. Tanpa itu, program bisa kembali menampilkan menu walaupun user merasa sudah memilih keluar.

Pesan keluar tetap penting, tetapi pesan saja tidak menghentikan program. Jadi, biasakan menulis keduanya: tampilkan pesan selesai, lalu break.

Bug umum

Program menampilkan “selesai”, tetapi menu muncul lagi. Biasanya penyebabnya adalah break belum ditulis atau indentasinya salah.

Cara Debug Loop

Bug pada loop sering muncul karena alur tidak berhenti di tempat yang kita harapkan. Saat debugging, tanyakan: “Kondisi apa yang membuat loop berhenti?” dan “Apakah perintah berhentinya benar-benar dijalankan?”

Pada contoh ini, program sudah mengenali pilihan 0, tetapi belum diberi perintah untuk keluar dari loop. Solusinya kecil, tetapi efeknya besar.

Strategi cepat

Tambahkan print sementara seperti print("masuk menu keluar") untuk memastikan cabang yang benar memang dijalankan.

Loop Membutuhkan Debugging yang Tenang

Begitu ada loop, satu bug kecil bisa terasa seperti program “muter-muter”. Karena itu, debug secara bertahap. Jangan langsung mengubah banyak bagian sekaligus.

Cek dari hal paling dasar: apakah pilihan user terbaca? Apakah nilainya berupa teks atau angka? Apakah cabang if/elif yang benar dijalankan? Apakah break ada di tempat yang tepat?

Prinsip

Ubah satu bagian, lalu test lagi. Jangan memperbaiki lima hal sekaligus kalau belum tahu penyebabnya.

Validasi Bertahap

Di sesi 16, input salah boleh dicatat sebagai batasan prototype. Di sesi 17, kamu mulai bisa membuat program lebih ramah dengan try/except sederhana.

Namun, jangan sampai validasi membuatmu kehilangan fokus utama. Prioritas sesi ini tetap main menu loop. Validasi cukup digunakan pada input angka yang paling rawan membuat program berhenti.

Contoh error

int("dua juta") akan memunculkan ValueError. Dengan try/except, program bisa memberi pesan lalu kembali ke menu.

Test Case untuk Menu

Loop membuat kemungkinan alur menjadi lebih banyak. User bisa memilih fitur 1 lalu keluar, memilih fitur 2 lalu fitur 1, atau salah mengetik dulu baru memilih menu yang benar.

Karena itu, test case perlu menuliskan urutan input. Jangan hanya menulis “fitur berjalan”. Tulis pilihan yang dipakai, data yang dimasukkan, dan output yang diharapkan.

Format catatan

Input: 9 → 0. Expected: program menampilkan pesan pilihan salah, lalu selesai saat user memilih 0.

CLI Tetap Punya UX

UX bukan hanya tentang warna dan tombol. Dalam CLI, UX terlihat dari teks yang mudah dipahami, urutan menu yang masuk akal, dan pesan yang membantu user saat salah input.

Gunakan nama fitur yang jelas. Hindari label terlalu pendek seperti “Menu A” atau “Fitur X” kalau user tidak tahu maksudnya.

Tips kecil

Letakkan pilihan keluar di bawah dengan angka 0. Ini pola yang cukup umum dan mudah diingat.

Komentar yang Bernilai

Komentar terbaik biasanya menjelaskan alasan, bukan hanya menyebut nama perintah. Di main menu, komentar bisa menjelaskan mengapa while True dipakai atau mengapa pilihan menu dibaca sebagai teks.

Namun, jangan menulis komentar terlalu banyak sampai kode susah dibaca. Pilih bagian yang benar-benar membantu pembaca memahami alur.

Aturan praktis

Kalau komentarnya hanya mengulang kode, mungkin tidak perlu. Kalau komentarnya menjelaskan keputusan desain, itu berguna.

Pitch Deck Tidak Terpisah dari Coding

Setelah prototype berubah, pitch deck juga perlu diperbarui. Kamu bisa menambahkan screenshot output menu, menjelaskan pilihan fitur, dan menulis alur demo.

Demo plan yang baik tidak harus panjang. Cukup jelaskan urutan yang akan ditunjukkan: buka menu, pilih fitur, masukkan data dummy, tampilkan hasil, lalu keluar dari program.

Contoh alur demo

1 → isi data budget → 4 lihat ringkasan → 0 keluar.

Data Aman Saat Demo

Project ini bertema finansial, jadi kamu harus ekstra hati-hati. Walaupun aplikasinya hanya prototype, jangan memakai data uang asli yang bisa mengarah ke identitas pribadi.

Untuk presentasi dan pitch deck, gunakan data dummy yang terlihat realistis tetapi bukan data pribadi. Screenshot output CLI juga harus dicek sebelum dikumpulkan.

Jangan masukkan

Password, nomor rekening, token, alamat rumah, data keluarga, atau catatan finansial asli.

Checkpoint Kualitas

Checklist ini membantu kamu melihat apakah project sesi 17 sudah memenuhi tujuan belajar. Kode yang panjang belum tentu bagus. Yang penting, struktur main menu jelas dan bisa dijelaskan.

Sebelum mengumpulkan, jalankan ulang notebook dari awal. Pastikan program tidak berhenti sebelum waktunya, tidak nyangkut ketika memilih keluar, dan tidak membingungkan saat input salah.

Refleksi Sesi 17

Kalau kamu bisa menjelaskan mengapa memakai while True, kapan memakai break, dan bagaimana pilihan user diarahkan ke fitur, berarti kamu sudah menangkap inti sesi ini.

Refleksi tidak perlu panjang. Tulis satu hal yang sudah berjalan, satu bug yang sempat muncul, dan satu hal yang ingin dirapikan di sesi berikutnya.

Target pemahaman

Kamu tidak hanya tahu kode menu, tetapi juga paham alur berpikir di baliknya.

Rangkuman

Main menu loop adalah langkah penting dari prototype sederhana menuju aplikasi CLI yang lebih nyaman dipakai. User bisa memilih fitur, mencoba alur berbeda, lalu keluar saat selesai.

Ingat pola utamanya: tampilkan menu → baca pilihan → jalankan fitur → kembali ke menu → keluar dengan break. Pola ini akan menjadi pondasi saat project dirapikan dengan function di sesi berikutnya.

Pesan terakhir

Menu yang baik membuat aplikasi terasa jelas untuk user dan lebih mudah dites oleh developer.
