Urutan kerja bot

Polling adalah proses mengecek data berkala, misalnya setiap dua detik pada simulasi ini. Threshold adalah batas angka: jika harga melewati batas beli atau jual, program menampilkan alert. Audit log adalah catatan yang menyimpan kejadian penting beserta waktu terjadinya.

Ketiganya punya fungsi yang berbeda. Polling menentukan kapan memeriksa. Threshold menentukan kapan alert aktif. Logging menjawab apa yang pernah terjadi dan kapan.

Pada notebook, polling dibatasi empat siklus dengan for. Ini cukup untuk memahami logika tanpa harus membuat program berjalan tanpa batas.

Jangan tertukar antara judul materi dan fitur yang sudah ada

Sesi 30 menggunakan requests.get() untuk mengakses endpoint API dan memeriksa respons JSON. Pada Sesi 31, kode guru menggunakan daftar [15600.0, 15400.0, 15750.0, 15900.0]. Tidak ada panggilan requests.get() dalam program Sesi 31.

Perbedaan ini penting saat menguji atau mempresentasikan proyek. Kita boleh mengatakan “bot mensimulasikan pemeriksaan berkala seperti sistem API”, tetapi tidak tepat mengatakan “program mengambil kurs terbaru dari internet”.

Versi berbasis API membutuhkan desain tambahan: endpoint, pengecekan HTTP, penanganan error, interval yang sesuai aturan layanan, dan informasi waktu pembaruan data.

Mengapa operator perbandingannya penting?

Program menggunakan dua nilai target sebagai konstanta: TARGET_HARGA_BELI = 15450.0 dan TARGET_HARGA_JUAL = 15800.0. Selama uji utama, pertahankan nilainya supaya hasil semua siswa dapat dibandingkan.

Jika harga kurang dari atau sama dengan 15.450, program menampilkan BELI. Jika harga lebih dari atau sama dengan 15.800, program menampilkan JUAL. Angka di antaranya menghasilkan STABIL dan tidak perlu dicatat sebagai alert.

Pada harga tepat 15.450, kondisi BELI sudah benar. Pada harga tepat 15.800, kondisi JUAL juga benar. Itulah sebabnya kita menggunakan <= dan >=, bukan hanya < atau >.

Membaca kondisi tanpa menebak

Baca kode seperti pertanyaan berurutan. Pertanyaan pertama: apakah harga sudah mencapai target beli? Jika iya, keluarkan ALERT BELI. Jika tidak, cek pertanyaan kedua: apakah harga sudah mencapai target jual? Jika iya, keluarkan ALERT JUAL. Jika kedua jawaban tidak, harga masih STABIL.

elif digunakan untuk kondisi berikutnya dalam satu rangkaian keputusan. else menjadi hasil cadangan jika semua kondisi sebelumnya salah.

Di program guru, cabang BELI/JUAL juga memanggil catat_log_alert(), sedangkan STABIL hanya mencetak informasi ke layar. Ini membuat jumlah log berbeda dari jumlah siklus pemantauan.

Uji batas sebelum menjalankan program

Dua harga pada latihan ini dipilih karena tepat sama dengan batas. Ini disebut boundary testing, yaitu menguji nilai di tepi sebuah kondisi. Banyak bug terjadi karena operator tidak sengaja ditulis dengan cara yang mengecualikan batasnya.

Mengapa memakai list empat harga?

List menyimpan empat harga yang kita ingin periksa secara berurutan. Pada setiap siklus, program mengambil satu elemen dari list dan memeriksanya menggunakan fungsi evaluasi_harga_pasar().

Keuntungan pendekatan ini adalah hasilnya bisa diprediksi sebelum kode dijalankan. Kita tahu harga 15.600 harus stabil, 15.400 harus beli, 15.750 stabil, dan 15.900 jual. Bila output berbeda, lebih mudah mencari sumber bug-nya.

Saat program dihubungkan ke sumber data real-time pada proyek lain, harga tentu tidak dapat dijamin muncul dengan urutan ini. Untuk Sesi 31, list simulasi menjadi dasar pengujian yang disepakati.

Mengapa while ini berbahaya?

Pada potongan kode ini, nilai harga selalu 15.000 dan kondisi harga <= 15450 selalu benar. Karena tidak ada perubahan nilai maupun break, loop tidak punya alasan untuk berhenti. Perintah print() terus berulang. Tanpa jeda, ini bisa membuat program menggunakan sumber daya secara berlebihan (busy waiting).

Agar aman, sebuah polling loop perlu strategi memperbarui data, menunggu jeda, menangani error, serta cara berhenti. Pada Student Project Sesi 31, kita menggunakan for dengan empat harga sehingga jumlah pemeriksaan sudah dibatasi.

Diskusikan perbedaannya: loop untuk latihan berakhir setelah empat iterasi; loop produksi memerlukan kontrol dan kebijakan layanan API.

Kenali tiga modul dan tiga konstanta

import time membuat fungsi time.sleep() tersedia. import datetime dipakai saat membuat timestamp di setiap catatan log. import os dipakai dalam sel pengecekan untuk mengetahui apakah file log sudah ada.

Apa saja yang perlu dicatat?

Audit log adalah catatan aktivitas penting yang membantu kita menelusuri kapan suatu peringatan muncul. Dalam aplikasi finansial, log dapat membantu pengujian dan audit. Namun file log ini hanyalah catatan simulasi, bukan bukti transaksi nyata.

Satu baris log memuat timestamp, jenis aksi (BELI atau JUAL), angka harga, dan keterangan singkat. Setiap kali kondisi alert terpenuhi, fungsi catat_log_alert() akan menambahkan baris baru ke berkas.

Untuk proyek ini, harga stabil tidak ditulis ke log. Maka empat siklus pemantauan hanya menghasilkan dua baris alert baru.

Bagaimana Python menyusun pesan log?

datetime.datetime.now() mengambil waktu saat fungsi dipanggil. strftime("%Y-%m-%d %H:%M:%S") mengubahnya menjadi teks tanggal dan jam dengan format mudah dibaca.

f-string memungkinkan kita menyisipkan nilai variabel langsung ke teks. Contoh {harga:,.2f} menampilkan 15400 sebagai 15,400.00. Tanda \n pada akhir string membuat catatan berikutnya dimulai di baris baru.

Dalam Student Project, kamu diminta melengkapi TODO A1 dengan menyusun pesan_log seperti contoh. Selanjutnya kamu harus benar-benar menyimpan teks itu ke file; membuat string saja belum menulis file.

Append vs write

Pada baris with open(..., "a", encoding="utf-8") as f:, Python membuka berkas dalam mode append. Bila file belum ada, Python akan membuatnya. Bila file sudah berisi catatan, baris baru ditambahkan di bagian akhir. f.write(pesan_log) menulis teks yang sudah disiapkan.

Mode "w" berbeda: berkas lama akan ditimpa. Ini adalah bug serius jika kamu ingin mempertahankan rekam jejak. Mode "r" hanya untuk membaca.

Catatan penting saat testing: karena memakai append, menjalankan simulasi dua kali akan menambah dua pasang alert (total empat baris baru), kecuali kamu menggunakan file log baru atau menghapus file lama dengan sengaja khusus untuk pengujian. Jangan keliru menyangka log yang bertambah itu tanda loop tidak berhenti.

Kenapa bukan while True?

Notebook guru dan siswa Sesi 31 memakai for, karena kita hanya perlu mengecek empat harga latihan. enumerate(data_simulasi_pasar, 1) menghasilkan pasangan nomor urut dan harga. Pada siklus pertama, misalnya, i=1 dan harga_dummy=15600.0.

Apa yang sebenarnya terjadi?

Fungsi time.sleep(2) menghentikan eksekusi kode Python sementara selama sekitar dua detik. Pada proyek ini, fungsi tersebut berada di dalam loop, setelah satu harga selesai dievaluasi. Karena ada empat iterasi, fungsi sleep dipanggil empat kali (termasuk sesudah siklus terakhir).

Nilai dua adalah jumlah detik, bukan jumlah pengulangan. Mengubahnya menjadi time.sleep(0) membuat program tidak memberikan jeda yang berarti. Sementara itu, time.sleep(120) akan membuat siswa menunggu terlalu lama untuk sekadar latihan.

Di layanan API sungguhan, jeda harus mempertimbangkan ketentuan rate limiting penyedia data.

Apa yang perlu dipastikan tentang tipe data?

"15400" adalah string karena memakai tanda petik. Sementara itu, 15450.0 adalah float. Python tidak mengizinkan perbandingan urutan langsung antara string dan float, sehingga akan muncul TypeError.

Jika data valid dalam bentuk teks angka, kamu dapat menggunakan float() untuk mengubahnya. Namun input seperti "tidak ada" akan menyebabkan ValueError saat dikonversi. Untuk aplikasi sungguhan, penanganan try-except dan validasi format masih diperlukan.

Pada empat angka simulasi bawaan, setiap elemen sudah bertipe float; kesalahan ini menjadi penting jika kamu mengubah input atau mengembangkan bot berbasis data API.

Challenge mandiri dari Teacher Project

Persentase perubahan membandingkan harga sekarang terhadap harga awal: (harga_sekarang - harga_awal) / harga_awal * 100. Pada daftar ini, harga pertama adalah 15.600. Jika harga sekarang 15.400, hasilnya sekitar -1,28%, artinya turun dari nilai awal.

Untuk menampilkan hasil dengan tanda plus atau minus, gunakan format {persen:+.2f}%. Tanda + pada format akan terlihat ketika nilai positif.
